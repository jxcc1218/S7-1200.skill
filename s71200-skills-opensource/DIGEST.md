## 一、这本手册蒸馏出了什么

原书约 1200 页（含附录 A–C），全部 52 个能力单元通过三重验证（来源充分性 / 可执行性 / 任务增益）与阶段 1.6 晋级门评审：7 个晋级为独立 Skill，45 个保留在路由入口内随取随用。所有卡片共享六段契约（R 原文引用 / I 自述 / A1 案例 / A2 触发 / E 执行步骤 / B 边界与失败模式），E 段全部带输入契约、判停点与完成标准。

### 7 个晋级 Skill（一句话版）

| # | Skill | 一句话 |

## 二、三个最危险的静默失败

这三个失败的共同点：**CPU 全程正常，不报任何错**——运行者以为系统在按组态工作。

1. **组态控制"标记不存在"的模块被静默忽略**（p121，卡 `config-control-absent-module-silent`）
   在控制数据记录中把某模块标为"不存在"后：写它的输出**不产生任何影响**，读它的输入**恒返回 0**，该模块不提供诊断、状态值永远"正常"，CPU 不报任何访问错误。程序里那段联锁逻辑从此在读一个永远为 0 的输入——而你唯一的线索是"一切诊断都正常"。

2. **MB_SERVER 默认把整个 Q 区开给任意 Modbus 客户端**（p827–828，卡 `mb-server-default-open-ports`）
   `QB_Count`/`IB_Read_Count` 默认 **65535**、`Start` 默认 0——即开箱即把全部输出区开放给网络上的任意客户端；手册给出的唯一安全措施是"限制客户端 IP"。不显式收窄保持寄存器范围，等于把物理输出裸露在网络上，且没有任何告警。

3. **AWP 注释里的空格疏漏让编译器静默生成错误代码**（p732，卡 `awp-space-silent-failure`）
   Web 自定义页面的 AWP 注释若名称子句引号/空格写错，编译**不报错**，但生成的 HTML 注释不是有效的 AWP 指令——页面静默不生效。你检查语法、检查权限、检查 Web 服务器状态都查不出问题，因为错误被"合法地"编进了输出。

> 同族还有：PWM/PTO 输出地址被静默收缴后程序照写不生效（p379）、证书参数不支持时静默降级、GET_ERROR 的 ENO 反向语义——本包 17 张卡带"静默失败"标记，以上是后果最重的三个。

## 三、三条不可逆操作

1. **V3.0→V4.x 迁移下载后不可撤销**（p1166–1167，卡 `v3-v4-migration`）
   V3.0 升 V4.x 必须换硬件；用 V4.x CPU 替换后一旦下载设备组态，就**无法再换回 V3.0**——下载前是最后后悔点。且 V3.0 密码会按固定映射降级（写/读保护→HMI 访问），V3.0 不存在"完全保护"等级。

2. **丢密码的唯一恢复路径 = 空卡擦除（删掉整个程序）**（p99–103，卡 `password-loss-blank-card-erase`）
   密码丢失没有"找回"，只有用空传送卡让 CPU 擦除内部装载存储器重来——程序、组态、密码全部清零。做之前先确认没有别的入口（如在线会话还活着）。

3. **Web 恢复中断 → 永久丢失保护等级**（p712/p982，卡 `protection-level-loss-on-restore-interrupt`）
   Web 备份/恢复流程一旦中断，CPU 的保护等级丢失，**手册未提供任何恢复步骤**——唯一手段是预防（恢复期禁循环上电、禁中断）。这是全包唯一一张"事后无解、预防即全部"的卡。

> 相关边界：S7-1200 **不支持安全擦除**（p957）——IT 侧的数据销毁要求在本设备上无法满足，处置停用 CPU 时只能物理控制存储卡。

## 四、"手册可信度"要点

这套蒸馏的可信度建立在"先审书、再蒸馏"上：阶段 0 批判 + 阶段 1.5 逐条回原文核验，产出 `_verify/澄清清单.md`。最终计数：**24 条内部自相矛盾（A1–A24）、22 条手册勘误（B1–B22），另有 5 条页码纠错（Z1–Z5）与 5 条新发现静默失败（S1–S5）**。矛盾与勘误不是花边——每一条都直接改写了对应能力卡的执行判据（B 段"矛盾/勘误取舍"行）。

### 举三例（每例都改变了"该怎么做"）

1. **Anonymous 用户：安全章节与通信章节互斥**（A1）
   安全实践反复要求"请勿启用 Anonymous 用户"，而 PUT/GET 远程访问的操作步骤第一步恰恰要求先启用 Anonymous（p136/p139 vs p141），手册未给取舍说明。本包的取舍判据落在访问控制卡：按任务分时启用——做远程访问时临时启用并事后关闭，长期态保持禁用；两章节各自照做都会与对方冲突，不能同时满足。

2. **表 9-103 标题把 UPPER_BOUND 误印成 LOWER_BOUND**（B1，p231）
   标题与内容相反——照标题引用会拿错指令的边界语义。勘误卡口径：以表内容实指的 `UPPER_BOUND` 为准。同族还有：章节标题误作 DeviceStates（实为 ModuleStates，p364）、Modbus 保持寄存器地址表"最大值"列数字粘连（"400990""4011920"，须按同页正文算例 40120 为准，p829）。

3. **32767 的四义歧义被两节分裂叙述**（A11）
   对照表（p947–948）只给"上溢"一种解释，完整解析方法在 p977——按单一页排查会把"断线"当"超量程"处理。这正是晋级卡 #3 存在的理由：把四种含义、判别顺序、处置分支合成一张决策卡。

### 使用者须知

- **版本强绑定**：本包全部口径来自 V4.7（12/2024）。SNMP 默认值在 V4.6 被翻转、MC 指令 ENO 语义在 V4.0 翻转、UMAC 仅 V4.7 存在——跨版本引用请先核对卡片标注的页码语境。
- **示例会过期**：手册自己的证书示例（p526）在 2024-08 已过期，而手册是 2024-12 版。凡涉及证书/时间的流程，卡内已标注"示例仅示范结构，不照抄参数"。
- **诚实缺口**：手册不给的（CP 1243-1 的 5V 耗值、保护等级恢复步骤、MRP 看门狗换算公式等），能力卡一律显式声明"手册未载/未给"，判停询问或指向外部手册，不外推、不编造。
