# power-budget-dual-rail — 5V/24V 双通道功率预算差额法

## R — Reading（原文）

> "如果超出 5 V DC 功率预算，可能无法将最大数量的扩展模块连接到 CPU。必须拆下一些扩展模块直到其功率要求在功率预算范围内。"（p41，5.2 功率预算）

> "如果 24 V DC 功率要求超出传感器电源的预算，则可以为系统增加外部 24 V DC 电源。必须将外部 24 V DC 电源手动连接到输入点或扩展模块上的继电器线圈。"（p41）

> "该 CPU 已分配驱动内部继电器线圈所需的功率。功率预算计算中无需包括内部继电器线圈的功率要求。"（p1154，表 B-1 前"说明"框）

> "I/O 需要 456 mA，而 CPU 只提供 400 mA。该安装额外需要一个至少为 56 mA 的 24 V DC 电源以运行所有包括的 24 V DC 输入和输出。"（p1154）

## I — Interpretation（自述）

这件事的本质是**两条独立的电流账**，不是一条：CPU 同时扮演两个供电角色——
1. **5 V DC 逻辑电源**：只喂扩展模块（SM/CM/SB）的总线电子部分。这笔账没有外部补救手段，超了就只能拆模块。
2. **24 V DC 传感器电源**：喂 CPU 本机输入点、扩展模块上的输入点和继电器输出线圈。这笔账超了可以加外部 24 V 电源补。

算法是三段式：按两张列（5V/24V）分别"CPU 预算 − 系统要求 = 带符号差额"。差额为正 = 组态可行；5V 差额为负 = 必须减模块；24V 差额为负 = 加外部电源（容量 ≥ |差额|）。**同一份模块清单要算两遍**，且两个数字互不混算。三条最易漏的定额都在 24V 列：本机 DI 每点 4 mA、扩展模块继电器线圈每个 11 mA、SB 输入每点 4 mA。另一个陷阱：CPU 本机继电器线圈的耗电已由 CPU 自己出，**不进**预算表；只有扩展模块上的继电器线圈才计 11 mA。模块自身的 5V/24V 耗值不在预算章节里，必须逐型号回附录 A 技术规范摘取——手册明确不给速查表。

## A1 — Application Example（书中案例）

**书中算例（表 B-1，p1154）**：CPU 1214C AC/DC/继电器（5V 预算 1600 mA / 24V 预算 400 mA）+ 1 SB 1223 + 1 CM 1241 + 3 SM 1223 DI8/继电器 DO8 + 1 SM 1221。

逐行复算（手册数字，已回原文核对）：
- 5V 列：SB 1223 = 50 mA；CM 1241 = 220 mA；3 × SM 1223 = 3 × 145 = 435 mA；SM 1221 = 105 mA → **总要求 810 mA** → 差额 1600 − 810 = **+790 mA**。
- 24V 列：CPU 本机 14 点输入 = 14 × 4 = 56 mA；SB 1223 输入 = 2 × 4 = 8 mA；3 × SM 1223 输入 = 3 × 8 × 4 = 96 mA；3 × SM 1223 继电器线圈 = 3 × 8 × 11 = 264 mA；SM 1221 输入 = 8 × 4 = 32 mA → **总要求 456 mA** → 差额 400 − 456 = **−56 mA**。
- 手册结论：5V 够用；24V 缺 56 mA，**至少加一个 56 mA 的外部 24V 电源**。p1155 表 B-2 提供同样结构的空白模板可直接套用。

## A2 — Future Trigger ★（触发场景与语言信号）

**触发场景**：
1. 新项目选型：定了 CPU 型号，要决定"带几个 SM/CM/SB 带得动"——"帮我算算 1214C 最多能挂几个模块 / How many SMs can this 1214C drive?"
2. 扩容改造：现场要在已有 CPU 右侧再加一块信号模块，问"加一个 SM 1223 会不会超 / will adding one more module overload the CPU?"
3. 选了外部 24V 电源，问"要多大容量 / what size 24V supply do I need?"——答案必须是带符号差额的绝对值。
4. 排查"加了模块之后 CPU 行为怪异/输入读数不可靠"，怀疑供电不足（对应 p1153"超出功率预算会导致无法预测的行为"）。
5. 画接线图前做电源分配：哪些负载吃 CPU 传感器电源、哪些吃外部电源、两边 M 端怎么接。

**语言信号**：功率预算 / power budget、5V/24V 预算 / current budget、传感器电源 / sensor supply、带不带得动 / headroom、差多少 mA / current shortfall、外部 24V 电源 / external 24V supply。

**与相邻 skill 的区分**（初稿，阶段 3 回填）：本卡只回答"电流账怎么算、差额怎么处置"。查某个模块的具体耗值/规格 → router 规格查询；接地、M 端子等电位、并联禁令等接线规则 → router（本卡 B 段只列其位置不展开）。

## E — Execution（可执行步骤）

**输入契约**（缺一项先询问，不得猜值）：
- CPU 型号及输出类型（决定 5V/24V 两列预算与是否本机含继电器）；
- 完整模块清单（SM/CM/SB 各型号与数量）；
- 每个模块的 5V/24V 耗值（来自附录 A 技术规范，如 SM 1223 = 145 mA 5V；**手册无速查表，逐型号摘取**）；
- CPU 本机 DI 使用点数、各扩展模块 DI 点数、扩展继电器输出点数。

**计算顺序与公式**（约定：单位一律 mA；差额保留符号；预算取附录 A 表值）：
1. **Step 1 前置门**（判停点）：核对扩展数量上限——SM 数 ≤ 型号上限（1211C=0 / 1212C=2 / 1214C/1215C/1217C=8）、CM ≤ 3、SB+CB+BB 合计 ≤ 1（p1153）。任一超限 → 直接停止，先改组态，不进入计算。✅ 完成标准：清单通过三条上限。
2. **Step 2 双列减法**：5V 列：预算 − Σ(各扩展模块 5V 耗值)；24V 列：预算 − [CPU 本机 DI 点数×4 + Σ(扩展 DI 点数×4) + Σ(扩展继电器线圈数×11)]。✅ 完成标准：两个带符号差额都算出，且与逐行算式自洽（合计行能对上）。
3. **Step 3 分支处置**（判停点）：
   - 5V 差额 < 0 → **只能**拆扩展模块重算，回到 Step 2；
   - 24V 差额 < 0 → 外部 24V 电源，容量 ≥ |差额|，并执行并联禁令检查（不与 CPU 传感器电源并接，分区供电，p42/p1153）；
   - 两者 ≥ 0 → 组态可行，按表 B-2 格式出核算表。

**输出契约**：一张两列差额表（字段：CPU 功率预算 5V/24V｜系统要求 5V/24V｜总电流差额 5V/24V），每行带乘法算式；结论行给出三个值之一（可行/拆模块/加 ≥|差额| mA 的外部电源）+ 两条 M 端同电位提醒。**容差/舍入约定**：手册未规定舍入——按整数 mA 精确相减，不向下取整留"虚余量"。

## B — Boundary（边界与失败模式）

- **反场景**：只查某个模块"耗多少电流"→ 这是查表不是核算；交流侧（CPU 供电电压/浪涌电流）不是本卡对象；接地与 EMC 布线 → router。
- **手册警告的失败模式**：①超 5V 预算 → "无法预测的行为"（p1153）；②外部 24V 电源与传感器电源**并联** → 两电源冲突、寿命缩短或立即故障（p42 警告框，两者必须分区分供电）；③非隔离 M 端子接不同参考电位 → 无法预测的电流、PLC 损坏（p42/p1154 警告框）。这三条都是"接上了也上电、但运行不确定"级。
- **易漏算项（验证阶段实证）**：CPU 本机继电器线圈被误计入预算（p1154 说明框明说不用）；扩展继电器线圈 11 mA/个整组漏算；SM 数量上限 1211C=0 被忽略。
- **模块名先对表再查耗值（阶段 4 压测实证）**：模块名先对表附录 C 区分 CM=通信模块（表 C-4）/ CP=通信处理器（表 C-6），再回附录 A 查耗值，防止拿错表；CM 1243-1 为表外名（实为 CP 1243-1，以太网接口属通信处理器），其 5V 耗值手册未载 → 按输入契约"缺值先询问，不得猜值"判停询问，不外推。
- **作者盲点（阶段 0 批判）**：手册全文没有 24V 耗值速查表，三条定额（4 mA/点、11 mA/个）只从表 B-1 算例中"读出"，换别的模块仍须回附录 A——手册未把这做成通用口径，本卡沿用此边界，不外推成"所有输入都是 4 mA"。
- **相邻易混淆**：与"接线/接地审查"同域但契约不同——本卡输出的是数字差额表，不是接线检查单。
