# emergency-ip-recovery — 紧急（临时）IP 恢复：彻底连不上 CPU 时的做法

## R — Reading（原文）

> "如果在下载项目时遇到以下问题，则 CPU 可能无法访问：CPU 的 PROFINET 接口的 IP 地址与网络上的其它设备重复。CPU 的子网不正确。子网掩码使 CPU 无法访问。"（p645）

> "可以在以下条件下分配紧急 IP 地址：STEP 7 中的设备组态在 IP 协议中有'在项目中设置 IP 地址'(Set IP address in the project)。CPU 处于 STOP 模式。"（p645）

> "可以设置紧急 IP 地址，而不受 CPU 的保护等级限制。使用 DCP 工具设置临时 IP 地址后，CPU 上的维护 LED 指示灯将亮起。诊断缓冲区还包括一个指示用户已启用以太网接口的紧急地址的条目。"（p646）

> "可以通过关闭和打开 CPU 来重置紧急 IP 地址。在分配了紧急 IP 地址后，可以使用 CPU 的有效 IP 地址下载 STEP 7 项目。下载项目后，重新启动 CPU。"（p646）

## I — Interpretation（自述）

这是"**不知道 CPU 的 IP、网上完全找不到它**"时的最后手段。三个典型成因把 CPU 变成网络孤岛：IP 与别的设备重复、子网设错、子网掩码把 CPU 隔离——三种情况下 STEP 7 都再也无法按 IP 访问它。解法不是改回 IP（改不了），而是用 DCP 协议（二层发现，不依赖 IP）给 CPU 临时塞一个**紧急 IP**。生效有三个硬性面：①项目组态必须选了"在项目中设置 IP 地址"；②CPU 必须已在 STOP；③用 DCP 工具（如 SAT 的"DCP 设置 IP 地址"）。成功判据有两个，**要两个都出现**：维护 LED 亮起 + 诊断缓冲区多出"启用紧急地址"条目。拿到紧急 IP 后立即用它下载含有效 IP 的项目并重启。关键安全属性：此流程**不受保护等级限制**——任何能物理接触网口的人都能做，它同时是救命稻草和攻击面。临时性：关电再上电即被重置，所以恢复有效组态前不能断电。边界：它只是把 CPU 拉回可达状态，**不解决** IP 冲突/子网错误的根因。

## A1 — Application Example（标注演练：验证记录 T1 六步演练复现）

**【合成演练（T1 纸面推演，逐条对应 p645–646 原文），原书未提供成例】**
场景：S7-1214C 下载项目后无法按 IP 访问；已知项目里该 CPU 勾选了"在项目中设置 IP 地址"；现场网段 192.168.2.0/24，拟用 192.168.2.77 做紧急 IP；面板 RUN 灯为绿。
1. 前提 1 ✓（在项目中设置 IP）；前提 2 ✗（RUN）→ **第一步必须先切 STOP**，否则 DCP 设 IP 不生效（判停点）。
2. 用 DCP 工具（例：SIMATIC 自动化工具 →"DCP 设置 IP 地址"）写入 192.168.2.77。
3. 双判据核验：维护 LED 亮 + 诊断缓冲区出现"用户已启用以太网接口紧急地址"条目——只有 LED 亮而无缓冲区条目 → 记为异常，不进入下一步。
4. 用 192.168.2.77 建立 STEP 7 连接，下载含**有效 IP** 的设备组态。
5. 下载完成后重启 CPU，使有效 IP 生效；验证按新 IP 可访问。
6. 若放弃恢复：直接关/开 CPU 重置紧急 IP——**在下载有效组态前断电会退回不可访问状态**。
复算依据：每一步与 p645–646 原文逐条对应（前提顺序、双判据、两条恢复规则），未补造原文外步骤；DCP 工具具体命令名手册只举 SAT 一例（"例如"），其它工具不冒充。

## A2 — Future Trigger ★

**触发场景**：
1. "不知道 CPU 的 IP 是多少，网上也搜不到 / I don't know the CPU's IP address"——未配 IP、换了 CPU、或 IP 丢失。
2. "下载新项目后彻底连不上 CPU 了"（IP 重复/子网错/掩码错三成因）。
3. "被锁在门外了：不知道密码也连不上，还有救吗"——紧急 IP 不受保护等级限制，是唯一能不凭密码接触的通道。
4. 同网段有人把 CPU 的 IP 配重了，多台设备互相打架。
5. 拿到一台来路不明的 CPU，要把它拉回可管理状态。

**语言信号**：紧急 IP / temporary IP / emergency IP、找不到 CPU / cannot reach CPU、IP 重复 / duplicate IP、DCP、维护 LED / MAINT LED、彻底连不上 / totally inaccessible。

**与相邻 skill 的区分**（初稿）：**"不知道 IP"或"完全失联"** → 本卡；**"知道 IP，但某个服务不通"**（端口被占/防火墙挡）→ port-state router 卡；**"新 CPU 第一次分 IP"**（在线分配：更新可访问设备 → 若只显示 MAC 即无 IP → 在线和诊断 → 分配 IP，p487）→ first-ip router 卡——本卡与 first-ip 的分流判据：手上有可用项目组态且 CPU 失联走本卡；全新 CPU 正常发现走 first-ip。

## E — Execution（可执行步骤）

**输入契约**（缺则先问，缺前提时不猜）：①CPU 是否确认在网络上物理可达（Link 灯）；②项目中该 CPU 的 IP 协议是否为"在项目中设置 IP 地址"；③能否把 CPU 切到 STOP（安全前提：设备停机是否被允许）；④拟用的紧急 IP（与编程设备同网段且确认空闲）；⑤现场有哪种 DCP 工具（SAT 或其它，工具名不冒充）。

**步骤**：
1. **Step 0 前提门**（判停点）：核对"在项目中设置 IP 地址" ✓ 与 CPU 处于 STOP ✓。任一不满足 → 先补前提（把 CPU 切 STOP；组态不对则走 first-ip 路径重估）。✅ 完成标准：两个前提都有证据。
2. **Step 1 写紧急 IP**：用 DCP 工具把设备 IP 设为选定的紧急地址。✅ 完成标准：工具回执成功。
3. **Step 2 双判据核验**：①CPU 维护 LED 亮起；②诊断缓冲区（以紧急 IP 连上后查看）出现启用紧急地址条目。两者齐 → 成功；只有 LED 无条目 → 停止并记录异常。✅ 完成标准：两项证据可指认。
4. **Step 3 下载有效组态**：用紧急 IP 建立连接，下载含正确 IP/子网的 STEP 7 项目；完成后**重启 CPU** 使有效 IP 生效。✅ 完成标准：按有效 IP 可访问。
5. **Step 4（可选）重置临时 IP**：如需丢弃，关/开 CPU 即重置——**先下载有效组态，再考虑断电**（顺序不可反）。
6. **Step 5 根因闭环**：查并修三成因之一（IP 唯一性可用"扩展的下载到设备"对话框核对全网唯一性，p578）；根因不修，复发只是时间问题。

**输出契约**：恢复记录（字段：时间｜CPU 检修号｜三成因判定｜使用的 DCP 工具｜紧急 IP｜双判据结果｜下载的有效 IP｜重启确认）+ 根因结论。**约定**：手册未给校验和/超时参数——工具超时重试次数为现场约定，不写进手册口径。

## B — Boundary（边界与失败模式）

- **反场景**：知道 IP 但 102/80/443 某端口不通 → port-state；新 CPU 首次配 IP → first-ip；IP 冲突只发生在运行期且 CPU 仍可达 → 直接改 IP（注意子网外 = 停所有数据交换，p490 警告），不必动用本卡。
- **手册警告的失败模式**：①前提不满足时 DCP 设 IP 无效——最常见的是忘了先切 STOP；②"临时"是字面意思：**关闭/打开 CPU 即重置**，若在重置前没下载有效组态，CPU 立刻回到不可访问；③**不受保护等级限制** = 物理接触网口即可绕过访问控制（p473 物理访问警告同理）——必须配机柜锁/物理访问管控。
- **根因边界**：本流程不修 IP 重复/子网错误本身；修完可访问性后必须回 Step 5。
- **A15 循环上电口径（不得混用）**：本卡"关/开 CPU 重置紧急 IP"是**单次人为动作**；p455"对 CPU 循环上电以确保滤波时间生效"（滤波时间场景）与 p982"恢复操作时**请勿**对 CPU 进行循环上电"（备份恢复场景）是另外两个语境——三处口径不同**不构成取舍矛盾**，但在备份/恢复进行中绝不许循环上电（否则可能丢失保护等级，p982 警告）。
- **阶段 0 批判盲点**：手册只举 SAT 一个 DCP 工具例（"例如"），未列其它可用工具清单；诊断缓冲区条目的具体文本手册未全文引用——本卡不补造，判据以"存在启用紧急地址条目"为准。
- **相邻易混淆**：与 first-ip 卡共享"连不上/分 IP"触发词；分流 = 有组态救失联（本卡）vs 无组态起头建联（first-ip）。
