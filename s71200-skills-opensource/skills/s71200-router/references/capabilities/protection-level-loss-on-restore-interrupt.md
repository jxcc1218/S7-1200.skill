# 能力卡：恢复中断→永久丢失保护等级（预防判据：恢复期禁循环上电）

## R（原文引用）
> "使用恢复操作的执行过程中，会显示一系列过程消息，用户必须重新进入用户登录界面输入密码。每个过程步骤顺利完成后，都会显示以下完成指示以及用于重新加载页面的链接。"
> （恢复 PLC 流程，p712；配套约束：恢复中断的后果与循环上电禁令——手册未提供恢复步骤的补救路径，预防为唯一手段，见 A15 口径 p455 vs p982 的取舍）
> ——《S7-1200 系统手册》V4.7，13.7 标准 Web 页面 > 备份/恢复 PLC

## I（自述）
通过 Web 服务器"恢复 PLC"（在线备份恢复）的过程跨越多个步骤（上传备份→逐过程消息→重新登录输密码→复位完成）。风险判据：恢复过程中断（断电/断网/强制循环上电）可能导致保护机密组态数据的密码/保护等级**永久丢失**——而手册**没有提供恢复该丢失的步骤**（诚实缺口，C-959 needs_review 不采信）。因此本卡是预防型契约：恢复前查电/网稳定、恢复中禁止断电与循环上电、恢复后按清单验证保护等级仍在。注意 A15 矛盾的取舍：p455 允许"循环上电"评估存储卡，p982 禁止循环上电——本域（恢复过程）取 p982 口径，禁止。

## A1（合成演练，含可复算数值）
原书未提供数值算例。合成演练：恢复 80 MB 备份（规模示意），过程消息走 4 步、中段要求重新登录。判停点：任一步骤失败 → **不要**拔电/循环上电"重来一遍"，保持 CPU 供电，按页面指示重试或转 STOP 用 STEP 7 路径处理。恢复完成验证清单：访问等级密码、机密数据密码、Web 用户、IP 与组态一致性逐项确认。

## A2（未来触发）
- 场景：计划用 Web 在线备份做恢复；恢复做到一半断了；事后发现保护等级丢失想找回。
- 语言信号：中"恢复备份中断／保护等级丢了／恢复 PLC 能不能断电"；英"restore interrupted / protection level lost / online backup restore"。
- 相邻区分：备份创建（权限与 STOP 前提）→ Web 域 router；复位出厂（主动清场，有完整步骤）→ factory-reset 卡；换件密码处置 → cpu-swap 卡。

## E（执行步骤）
1. 输入契约：备份文件来源与内容已知性（恢复未知备份是 p712 警告项）+ 恢复窗口内的供电/网络保障。
2. 预检：CPU IP 与备份 IP 不一致的处置预案（恢复后 >5 分钟显示"复位 CPU" → 改 PC IP 到备份地址段，p712 说明）。
3. 执行恢复：按页面过程消息走，中途重新登录输密码。
4. 铁律：恢复全程禁止断电/循环上电（本域取 p982 禁令口径）。
5. 完成后验证：保护等级、密码、Web 用户、组态一致性逐项确认。
6. 完成标准：验证清单全绿；任一项缺失 → 报告"手册无恢复步骤"并按事故处理（不得补造流程）。

## B（边界）
- 反场景：日常固件更新/存储卡评估（那些场景允许受控重启，按各自卡执行）。
- 手册诚实缺口：保护等级丢失后的恢复步骤手册未给出——能力卡与回答都必须显式声明，不得虚构。
- 矛盾/勘误（A15 取舍判据）：p455"循环上电评估存储卡" vs p982"不要循环上电"——存储卡评估域允许、恢复/清场域禁止；引用时带场景限定。
- 外链缺口：无。
