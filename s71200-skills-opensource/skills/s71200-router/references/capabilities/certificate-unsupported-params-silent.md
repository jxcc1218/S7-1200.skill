# 能力卡：证书管理器表外参数『只是不工作』不报错

## R（原文引用）
> "说明：虽然可通过'证书管理器'(Certificate manager) 选择不受支持的证书参数，但仅可使用上表中列出的建议证书参数。使用表中未列出的证书参数可能出现通信问题或导致通信服务不可运行。"（p480）
> "证书参数 RSA 4096 的最小值扫描周期 (页 76)显著增加，利用此参数，至少可将 60% 的扫描周期负载分配给通信。"（p479）
> ——《S7-1200 系统手册》V4.7，12.5 支持的证书

## I（自述）
证书管理器允许你在 UI 里选中**表外**的证书参数（加密方法/参数不在 p479 推荐表内），但设备只会"不工作"——通信问题或服务起不来，**没有明确报错指回证书参数**。支持矩阵（p479 表）：EC prime256v1 / EC secp384r1 / RSA 2048 三者覆盖 Web 服务器、安全 PG/PC+HMI、安全 OUC；**OPC UA 仅 RSA 2048**。性能陷阱：RSA 4096 会显著增加最小扫描周期（通信至少占 60% 周期负载），属静默性能劣化。Z1 勘误：该支持表精确位置 p479–480（"12.5 支持的证书"），不是 p505–506（那是 TCON_QDN_SEC 结构表）。

## A1（合成演练，含可复算数值）
原书未提供数值算例。合成演练：为 OPC UA 服务器选 EC secp384r1（表内对 Web/OUC 支持，但 OPC UA 列"不支持"）→ 证书可生成，OPC UA 通道建立失败且无指向性错误。整改：OPC UA 一律 RSA 2048。性能核算：启用 RSA 4096 → 预留通信负载 ≥60%（p479 口径），若现周期 150 ms，通信占比上限即被抬高——先核通信负载组态再上 4096。

## A2（未来触发）
- 场景：配好证书后 HTTPS/OPC UA/安全 OUC 连不上且报错不指向证书；安全评审选加密套件；周期莫名变长。
- 语言信号：中"证书参数不支持／RSA 4096／OPC UA 用什么证书"；英"unsupported certificate parameters / RSA 4096 scan cycle / OPC UA certificate"。
- 相邻区分：证书时间无效（模块日期不对，80E2 类）→ 通信错误码域；"仅 HTTPS"默认态争议（A18）→ Web 域卡 B 段；OPC UA 安全策略默认（A16"无安全"默认开启）→ OPC UA 域卡。

## E（执行步骤）
1. 输入契约：通信服务清单（Web/PG-HMI/OUC/OPC UA）+ 拟用证书参数。
2. 对照 p479 表逐服务判定：参数在服务列"支持"才可用；OPC UA 仅 RSA 2048。
3. 表外参数处置：UI 能选 ≠ 支持——换表内参数。
4. 性能核查：选 RSA 4096 前，确认通信负载组态可承受（≥60% 周期让渡）。
5. 静默失败自查：服务起不来且错误不指证书 → 第一步核对证书参数表，再查时间/信任链。
6. 完成标准：所有服务证书参数均在支持表内，安全通道逐一实测建立。

## B（边界）
- 反场景：证书过期/不受信（时间与 CA 问题）；OPC UA 客户端策略不匹配（客户端侧协商问题）。
- 手册口径：p480"可能出现通信问题或导致通信服务不可运行"是后果的全部描述——手册不保证任何表外参数行为，勿引用表外组合。
- 矛盾/勘误（Z1 已核）：支持表页码 p479–480；S2：RSA 4096 ≥60% 扫描周期负载。
- 外链缺口：证书生成/分配操作细节 → STEP 7 Information System（p479 指引）。
