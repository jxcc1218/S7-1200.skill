# 能力卡：超出 5V 功率预算继续挂扩展模块的后果（不可预期行为）

## R（原文引用）
> "警告：超出功率预算带来的风险。超出功率预算会导致无法预测的行为。请使用以下信息作为指导，确定 CPU 可为您的组态提供多少电能（或电流）。运行不确定可能导致死亡、人员重伤和/或财产损失。"
> ——《S7-1200 系统手册》V4.7，附录 B，p1153

## I（自述）
超 5V 预算不是"报错后停机"的失败模式，而是**继续运行但行为无法预测**：CPU 不会在组态或下载阶段拒绝超预算组态，运行中出现的问题也不带"功率不足"标签。后果（手册未细列具体症状，只定性为 unpredictable behavior）可能与供电跌落、模块误动作相关，且在安全警告级别。因此 5V 差额必须当作硬约束在设计阶段闭环——这是"为什么每次扩容都要算预算"的根本理由。

## A1（合成演练，含可复算数值）
原书未提供超预算实测案例。合成演练：手册示例组态（5V 用 810/1600）再挂 6 个 SM 1223（145 mA/个）：810+870=1680 mA > 1600 mA，超 80 mA。手册算法（p1153）给出的唯一解是"拆下一些扩展模块直到其功率要求在功率预算范围内"——即移除 1 个 SM 1223 回到 1535/1600。手册未说明超限时具体表现，A1 结论止于"按规则必须减"。

## A2（未来触发）
- 场景：评审会上有人说"超一点 5V 应该没关系吧"；扩容后出现无诊断事件的怪问题，怀疑供电。
- 语言信号：中"超预算会怎样／5V 超了能不能跑／扩完模块乱跳"；英"exceed 5V budget / unpredictable behavior / undervoltage symptoms"。
- 相邻区分：怎么算差额 → power-budget-dual-column-procedure；算完为负怎么办 → power-budget-negative-asymmetric；本卡回答的是"为什么必须管"，提供安全警告原文作为否决依据。

## E（执行步骤）
1. 输入契约：任一组态的 5V 差额值。
2. 判定：差额 < 0 → 输出"不允许投入，必须整改"并引用 p1153 警告原文。
3. 给整改建议（减/换模块方案）→ 交 asymmetric 卡流程。
4. 静默失败自查：对"无诊断事件的随机异常"，若组态曾扩容，第一步复算 5V 预算而不是查程序——超预算无任何报错与诊断条目。
5. 完成标准：差额 ≥ 0 的复算记录，或明确的整改决定。

## B（边界）
- 反场景：差额已为正的组态（无需本卡）；24V 超限（可加电源，不属本卡）。
- 手册口径：后果只有定性描述"无法预测的行为"，**不得**替手册编造具体故障症状（哪些灯闪、哪些模块失效）——这是诚实缺口。
- 矛盾/勘误：无；B11（表 C-3 误译）不影响本条。
- 外链缺口：无（本条为手册自足的安全警告）。
