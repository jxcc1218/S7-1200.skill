# 能力卡：MB_CLIENT 超时静态变量取值口径（3.0s 默认 / 55s 硬上限 / 2.0s 响应）

## R（原文引用）
> "Blocked_Proc_Timeout Real 3.0 在 Modbus 客户端实例受阻后，移除该激活的实例前需等待的时间（秒）。……最大 S7-1200 限值是 55 秒。"
> "RCV_TIMEOUT Real 2.0 MB_CLIENT 等待服务器响应请求的时间（秒）。"
> ——《S7-1200 系统手册》V4.7，表 14-59 MB_CLIENT 背景数据块静态变量，p822

## I（自述）
MB_CLIENT 背景数据块里两个可写静态变量决定超时行为：Blocked_Proc_Timeout（默认 3.0 s，实例被阻塞后等待多久移除其激活状态，**硬上限 55 s**）与 RCV_TIMEOUT（默认 2.0 s，等待服务器响应）。响应超时到点 → STATUS=80C8（"服务器在指定的时间内未响应"，p824）。另注意 MB_Unit_ID 默认 255——TCP 用 IP 寻址，仅经 RTU 网关时才用该值。这些是静态变量（起始值或程序写入），改完须保证在 MB_CLIENT 执行前生效。

## A1（合成演练，含可复算数值）
原书未提供本条算例。合成演练：服务器实测应答 3 s，RCV_TIMEOUT=2.0 → 每次请求 80C8；改为 5.0 → 正常收数。另一例：程序把 Blocked_Proc_Timeout 设为 60 → 无效（超过 55 s 硬上限），取 55 才是最大合法值。数值全部可按 p822 表复算。

## A2（未来触发）
- 场景："Modbus 偶发 80C8 超时"；实例阻塞后新请求长时间不触发；调优轮询周期。
- 语言信号：中"MB_CLIENT 超时多少秒／80C8／Blocked_Proc_Timeout"；英"MB_CLIENT timeout / 80C8 no response / RCV_TIMEOUT"。
- 相邻区分：请求期内改输入导致不触发（无 80C8）→ mb-client-frozen-inputs——分流口诀：**有 80C8=等了但没回（本卡）**；**没有 80C8、请求根本没发=冻结输入问题（frozen 卡）**。

## E（执行步骤）
1. 输入契约：STATUS 值 + 现象描述 + 服务器实测响应时间。
2. 80C8 → 比对 RCV_TIMEOUT（默认 2.0 s）与服务器响应时间，调大到响应时间 + 余量。
3. 实例阻塞（REQ 无法再激活）→ 查 Blocked_Proc_Timeout 是否被改小/改超（≤55）。
4. 写入方式：DB 起始值或程序赋值，时序在 MB_CLIENT 执行前。
5. 完成标准：给出两个变量的建议值+理由，连续 10 轮请求无 80C8。

## B（边界）
- 反场景：连接根本建立不起来（CONNECT/IP 错误，80A4/80C6 等）→ 网络/组态排障，不是超时调参。
- 手册口径：80C8 只有"在尝试了组态的可重复尝试次数之后"才报告（p823），重试机制先于报错。
- 矛盾/勘误：无；MB_Unit_ID=255 默认值仅在网关场景有意义（p822 说明）。
- 外链缺口：无（本条手册自足）。
