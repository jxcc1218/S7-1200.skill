# 能力卡：V3.0→V4.x 迁移（下载后不可撤销 + 六类变化 + 保护等级映射）

## R（原文引用）
> "要将 V3.0 CPU 升级到 V4.x CPU，必须替换该 CPU 硬件。无法通过固件更新将 V3.0 CPU 升级到 V4.x CPU。"（p1166）
> "可以用 V4.x CPU 更换 V3.0 CPU，但下载组态后，无法用 V3.0 CPU 更换 V4.x CPU。……如果您尚未下载替换之后的设备组态，您可以撤消替换。但下载之后，便无法撤消从 V3.0 到 V4.x 的设备更换操作。"（p1167）
> "STEP 7 会将 V3.0 密码指定为 V4.x CPU 的'完全访问（无保护）'密码：无保护→完全访问（无保护）；写保护→读访问；写/读保护→HMI 访问。……对于 V3.0，不存在 V4.x 的'无访问（完全保护）'访问等级。"（p1167）
> ——《S7-1200 系统手册》V4.7，D.2 用 V4.x CPU 更换 V3.0 CPU

## I（自述）
V3.0→V4.x 是**换硬件**而非固件升级，且设备更换一旦下载**不可撤销**（未下载前可撤）。六类变化清单：①OB 可中断性——V3.0 项目所有 OB 默认不可中断，V4.x 按属性迁移后可按需改；②密码保护映射（如上：无保护→完全访问/写保护→读访问/写读保护→HMI 访问；V3.0 无"完全保护"档）；③Web 服务器——V4.x 不支持预组态 admin 用户；数据日志页"下载并清除"拆成下载+删除；④传送卡不兼容——V3.0 传送卡插入 V4.x CPU 会报错（p100/p1168），必须走 STEP 7 设备更换后重建 V4.x 卡；⑤GET/PUT 默认启用差异（V4.x 兼容信息提示）；⑥运动控制——不支持 V1.0/V2.0 库，编译时替换为兼容版本；TO 版本不自动升级。附带动作：检查并更新 SM/CM 固件（p1166）。

## A1（合成演练，含可复算数值）
原书未提供数值算例。合成演练：V3.0 项目（写/读保护）换 V4.5 CPU：设备更换 → 编译 → 下载前最后确认点（下载即不可逆）→ 下载后 CPU 访问等级自动映射为"HMI 访问"（按 p1167 表）→ 核对 Web 用户（admin 已失效，需重建）。判据：下载前归档项目（p1167 建议），下载后不得期望回退。

## A2（未来触发）
- 场景：老产线升级评估；"V3 程序直接拷到新 CPU 行不行"；迁移方案评审。
- 语言信号：中"V3.0 升级 V4.x／换 CPU 迁移／旧传送卡／admin 用户没了"；英"V3.0 to V4.x migration / device replacement irreversible / transfer card incompatible"。
- 相邻区分：同版本换件（密码/卡处置）→ cpu-swap-password-sdcard-disposal；"CPU 组态版本未知或不兼容"错误恢复（p948：取传送卡→STOP-RUN/MRES→复位出厂）→ 诊断域 router；CTRL_HSC 版本选择 → ctrl-hsc-ext-version-criterion。

## E（执行步骤）
1. 输入契约：现有项目版本（STEP 7 与 CPU FW）、目标 CPU 型号、密码/保护等级现状。
2. 前置：STEP 7 V13 及更早项目必须先升 V13 SP1/SP2 再升当前版（禁止复制程序逻辑升级，p1167 警告）。
3. 设备更换（TIA 中 V3.0→V4.x）→ 逐项过六类变化清单（OB 属性/密码映射/Web 用户/传送卡/GET-PUT/运动控制版本）。
4. 更换 SM/CM 固件（p1166 建议）。
5. 不可逆点控制：下载前归档项目+确认六清单完成；下载后放弃回退幻想。
6. 完成标准：新 CPU 在线运行，密码/权限/通信与旧系统行为对齐核查通过。

## B（边界）
- 反场景：V3.0 传送卡插入 V4.x CPU 的报错恢复（p100：取卡→STOP-RUN/MRES/循环上电，属事后修复不是迁移路径）；V4.x 内部小版本固件升级（走固件更新，非本卡）。
- 手册口径：p1168 运动控制 TO 参数名对照表（Config.General.LengthUnit→Units.LengthUnit 等）用于迁移脚本改写。
- 矛盾/勘误：无；A3（RUN 下载 DB 结构矛盾）属在线下载域，与本卡无关。
- 外链缺口：运动控制版本升级操作 → 指令导航/运动控制手册（D1）。
