# 能力卡：存储卡初始化批次与强制点随卡迁移陷阱

## R（原文引用）
> "如果使用存储卡传送用户程序，则该存储卡上的所有被强制元素都将被传送到 CPU。"（p967）
> "说明：强制值存储在 CPU 中，而不是强制表格中。不能强制输入（或'I'地址）或输出（或'Q'地址）。但是，可以强制外围设备输入或外围设备输出。"（p966）
> ——《S7-1200 系统手册》V4.7，15.17.5 强制功能 / 6.5 存储卡
> （初始化批次口径：SIMATIC 存储卡须为官方介质；卡的"初始化"即 STEP 7 创建传送/程序卡的过程，p102/104——不同批次/来源的卡在创建作业文件时统一被 STEP 7 初始化为可用格式，p101 评估逻辑）

## I（自述）
两个跨卡陷阱：①**强制点随卡迁移**——传送卡/程序卡装载的程序若含强制元素（I_:P/Q_:P），插卡评估后这些强制会在**新 CPU 上继续生效**（p967"继续强制程序中选择的点"）；调试期残留的强制值随卡扩散是危险品（且强制存于 CPU 而非表格，关软件不清除，p966）。②**卡初始化/复用纪律**——复用旧卡必须先删 S7_JOB.S7S 与旧文件夹；`__LOG__`/`crdinfo.bin` 不可删；卡写保护会让配方/数据日志指令报错（p99）。装载程序到**写保护卡**的 CPU 时无法初始化/更改强制（p967）。

## A1（合成演练，含可复算数值）
原书未提供数值算例。合成演练：调试台 CPU-A 强制了 QW2（外围输出）验证阀动作后未停强制 → 复制程序到传送卡 → 卡插产线 CPU-B 上电评估 → CPU-B 的 QW2 自动带强制值。排查特征：在线工具显示 CPU-B 有强制而本地无人强制过。处置：在线连接 CPU-B → 强制表格"停止强制"清除。

## A2（未来触发）
- 场景：换卡/批量装载程序后"设备莫名带强制值"；卡复用后配方/日志报错；卡初始化流程审查。
- 语言信号：中"强制值跟着程序走了／卡里的强制点／传送卡初始化"；英"forcing travels with the card / force values on new CPU / card initialization"。
- 相邻区分：PWM/PTO/HSC 占用点不可强制（不同机制）→ pwmpto 卡 B 段；RUN 下载的强制行为 → run-mode-download 晋级卡；SET_PWD 密码作业卡（p107）→ 存储卡密码域。

## E（执行步骤）
1. 输入契约：卡上程序来源（哪个 CPU 导出）+ 目标 CPU 清单。
2. 装载前检查：源 CPU 是否有活动强制（在线强制表格/程序状态查看强制符号）→ 有则先"停止强制"。
3. 卡复用检查：删 S7_JOB.S7S/旧文件夹、保留 __LOG__ 与 crdinfo.bin、滑开写保护（p102/104）。
4. 装载后验证：目标 CPU 上线 → 检查强制状态与关键输出点实际值。
5. 静默失败自查：目标机"无人强制却带强制" → 溯源卡上程序来源机的强制表。
6. 完成标准：目标 CPU 强制状态清零（或与设计一致）且卡作业文件合规。

## B（边界）
- 反场景：单机内正常调试强制（无跨卡迁移）；写保护卡上的程序运行（只读限制，p967）。
- 手册口径：强制的是外围地址（:P），不是过程映像 I/Q；强制在 CPU 持续生效直到在线清除（p966）。
- 矛盾/勘误：无；B10（IO-Link 订货号缺位 p1102）不影响本条。
- 外链缺口：无。
