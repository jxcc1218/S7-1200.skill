# 能力卡：数据日志容量公式（创建即全量预留，4 段字节预算 + 双上限）

## R（原文引用）
> "当指令返回 DONE = TRUE 时，DataLogCreate 指令为整个数据日志分配持久 CPU 内存。由于存在文件系统管理和相关的值，CPU 中所需的内存大于文件的大小。数据日志的持久性内存保持分配状态，直至 CPU 以下列方式之一取消分配内存：用户程序调用 DataLogDelete 指令；Web 服务器用户从 Web 服务器中删除数据日志；SIMATIC Automation Tool 用户从……删除数据日志。"（p396）
> "PLC 装载存储器的可用空间必须足够大，以确保成功创建数据日志。"（p395 RECORDS 参数）
> ——《S7-1200 系统手册》V4.7，10.9.2 数据日志

## I（自述）
数据日志容量模型的核心：**创建即全量预留**——DataLogCreate 一旦 DONE，整个 RECORDS×记录尺寸的持久装载存储器立刻被占满（不是边写边占）。四种字节段构成一条记录：①HEADER 行（≤255 字节/字符串）；②DATA 结构各列字节和；③时间戳（无=0）；④文件系统管理开销（>文件本身）。双上限：可用装载存储器（80B3 错误=空间不足）与文件系统最大值（8097）。结论：RECORDS 不能拍脑袋设大数，创建前必须做预算。

## A1（合成演练，含可复算数值）
原书未给完整算式（只给规则）。合成演练：记录=4×Real+1×Int（18 字节）+时间戳（timestamp=1，mm/dd/yyyy,hh:mm:ss ≈ 20 字节 CSV 文本）≈ 38 字节/条；RECORDS=100000 → 文件体 ≈ 3.8 MB，加管理开销 >3.8 MB，创建前须确认装载存储器剩余 ≥ 该值（精确阈值手册未给——B-x 诚实缺口）。80B3 出现即预算失败，减 RECORDS 或删旧日志重试。

## A2（未来触发）
- 场景：组态数据日志时问"RECORDS 能设多大／会不会把存储器占满"；80B3/8097 报错；预算装载存储器余量。
- 语言信号：中"数据日志容量／RECORDS 上限／装载存储器不够"；英"datalog capacity / RECORDS limit / load memory full"。
- 相邻区分：写满后的续接策略 → datalog-lifecycle-full-file；2KB 写入放大 → datalog-2kb-write-amplification（本卡管"占多少"，那卡管"写多频"）；配方 DB 的装载存储器占用是另一域（router）。

## E（执行步骤）
1. 输入契约：DATA 结构（各列类型）、HEADER 字符串、timestamp 取值、计划 RECORDS。
2. 估记录字节：Σ列宽 + 时间戳宽（0/20 字节量级）。
3. 估文件体：记录字节 × RECORDS + HEADER；结论标注"管理开销额外，精确值手册未给"。
4. 核对双上限：装载存储器余量（在线和诊断 > 存储）与文件系统最大值。
5. 超限处置：减 RECORDS / 减列 / 提示改用存储卡（频繁大量写入，p396）。
6. 完成标准：给出"记录 X 字节 × RECORDS = Y MB vs 可用 Z MB"的判定式。

## B（边界）
- 反场景：运行期写满（生命周期问题）→ lifecycle 卡；逐条小数据高频写（放大问题）→ 2KB 卡。
- 矛盾/勘误（A9 取舍判据）：p400"注意"明确"未完成 DataLogWrite 时掉电，正在传送的记录可能丢失"——"持久日志文件"指文件本体在闪存，**不等于每条记录掉电安全**；可靠性结论按 p400 执行，宣传"绝对不丢"是错误引用。
- 外链缺口：文件系统管理开销的精确字节数手册未提供（B-x N 类缺口）；CSV 区域格式转换（USA/UK→本地 Excel）见 p713/754（D12）。
