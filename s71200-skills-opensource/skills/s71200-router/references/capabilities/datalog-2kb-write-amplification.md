# 能力卡：数据日志每次写入至少占 2KB（写入放大与攒批对策）

## R（原文引用）
> "每次数据日志写入至少占用 2 KB 的存储空间。如果程序频繁写入少量数据，则每次写入至少占用 2 KB 的存储空间。采用某个数据块 (DB) 存放这些小数据量数据项，然后，以较小频次将该数据块写入数据变量不失为一种更好的实现方法。如果程序频繁写入大量数据日志条目，请考虑使用可更换的 SIMATIC 存储卡。"（p400）
> （同口径复现：p993 内部 CPU 内存保持性节）
> ——《S7-1200 系统手册》V4.7，10.9.2 数据日志

## I（自述）
数据日志存在**写入放大**：一次 DataLogWrite 无论记录多小，闪存层面至少动 2KB。高频小记录的后果：日志容量消耗 ≈ 次数×2KB（远大于记录本身），且循环写/删操作缩短存储卡寿命（p106 明确列 DataLogWrite 为循环写删风险操作）。手册官方对策两条：①**攒批**——小数据先累积进 DB，低频合并写一条大记录；②高频大量写入改用可更换 SIMATIC 存储卡。

## A1（合成演练，含可复算数值）
原书未提供数值算例。合成演练：每 100 ms 写一条 20 字节记录 → 每天 864000 次 × 2KB ≈ 1.6 GB 逻辑消耗量级（远超记录体 16.5 MB），闪存磨损与容量双双告急。攒批改造：600 条（60 s）合并写 1 条 12KB 记录 → 每天写入次数 = 86400/60 = 1440 次，次数降 600 倍。数值可按 2KB/次 与频率复算。

## A2（未来触发）
- 场景："日志量怎么掉得这么快"；存储卡寿命短；评审高频记录设计。
- 语言信号：中"写入放大／每次写至少 2KB／日志磨损"；英"2KB per write / write amplification / logging wear"。
- 相邻区分：容量预算（创建时占多少）→ datalog-capacity-budget；写满续接 → datalog-lifecycle-full-file；本卡只回答"多频小写为什么亏"。

## E（执行步骤）
1. 输入契约：写入频率（次/天）、单条记录字节、预期运行年限。
2. 估年消耗：次数 × 2KB（下限口径）对比日志容量预算。
3. 决策分支：消耗超标 → a) 攒批（DB 缓存、低频合并写）；b) 迁移到 SIMATIC 存储卡；c) 降频。
4. 验证：改造后统计每日 DataLogWrite 次数与容量下降曲线。
5. 完成标准：年消耗估算 ≤ 预算 80%，且满足业务数据粒度要求。

## B（边界）
- 反场景：低频大记录（放大可忽略，无需本卡）；配方导出等其他循环写删（p106 同风险清单，另域）。
- 手册口径：2KB 是**每次写入**的闪存占用下限，不是"每条记录 2KB"的文件尺寸——引用时勿混。
- 矛盾/勘误：无（p400 与 p993 两处口径一致，互为佐证）。
- 外链缺口：存储卡寿命的量化模型（P/E 次数）手册未给，仅定性（p106 影响因素）。
