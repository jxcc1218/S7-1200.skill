# 能力卡：端口-协议-默认状态表（仅 102/34964 默认开，谁启用它三分法）

## R（原文引用）
> "TCP 端口（被动）和 UDP 端口（被动）：20、80、102、5001、34962、34963、34964"
> （TCON 被动连接受限端口清单）——《S7-1200 系统手册》V4.7，p577
> （手册无"默认开启端口"专表；destinations 口径"仅 102/34964 默认开"为阶段 1.6 汇总结论：102 由 STEP 7/PUT-GET 通道使用，34964 由 PROFINET 现场设备使用，80/Web、5001/HMI 等仅当对应服务被启用时监听——见 E 段三分法）

## I（自述）
"连不上"排障的第一层分流：CPU 端口到底开没开。三步：①知道该服务的默认端口（S7/STEP7=102、Web=80/443、HMI=5001、PROFINET=34962–34964、OUC 自选被动端口）；②查该服务是否已启用/组态（未启用的服务端口不会监听——这是最常见原因）；③查防火墙与受限端口清单（p577：TCON 被动不得用 20/80/102/5001/34962/34963/34964）。A4 矛盾（p565 vs p577 两套黑名单）按下文 B 段取舍。

## A1（合成演练，含可复算数值）
原书未提供端口状态算例。合成演练：CPU 上 Web 服务器"无法访问"，telnet 80 不通。逐查：Web 服务器未在设备组态激活 → 激活并下载 → 80 端口监听。另一例：TCON 被动连接填 LocalPort=102 → 违反 p577 受限清单，必须改用非受限端口（p565 口径还排除 161）。

## A2（未来触发）
- 场景：用户问"CPU 的 XX 端口开没开／防火墙要放行哪些端口／TCON 该用哪个端口号"。
- 语言信号：中"端口不通／80 端口／34964／防火墙放行／被动端口"；英"port not open / firewall allowlist / restricted passive ports"。
- 相邻区分：**问"资源够不够、第 N 台连不上"** → connection-budget（晋级卡，负例必写：端口开没开→本卡，资源耗尽→晋级卡）；防火墙是黑名单还是服务未启用属本卡；PUT/GET 许可位（p141）→ full-protection/PUT-GET 域卡。

## E（执行步骤）
1. 输入契约：服务名（Web/HMI/S7/OUC/PROFINET）+ 现象（哪台设备连不上）。
2. 映射默认端口（102/80/443/5001/34962–34964/自定义）。
3. 三分法判定：a) 服务未启用/未下载组态 → 启用并下载；b) 端口落在受限清单（p577：20/80/102/5001/34962–34964）→ 换端口；c) 网络层防火墙 → 放行对应端口。
4. 验证：重新连接或用"扩展的下载到设备"扫描确认可达。
5. 完成标准：定位到 a/b/c 之一并给出对应处置，或升级到资源核查（转 connection-budget）。

## B（边界）
- 反场景：连接数预算问题（"最多接几台 HMI"）→ 晋级 connection-budget；IP 本身不知道 → emergency-ip-recovery / first-ip。
- 矛盾/勘误（A4 取舍判据）：p565（TCON 被动 UDP"除 161、34962–34964 外均可"）与 p577（TCP/UDP 被动列 20/80/102/5001/34962–34964）两套口径并存——取舍：p577 是显式"请勿使用"清单，按更严格的 p577 执行；p565 的 161 追加排除（SNMP）。两处均为受限清单，取并集最安全。
- 外链缺口：企业防火墙策略设计 → 网络安全白皮书（p82 引用西门子工业网络安全网站）。
