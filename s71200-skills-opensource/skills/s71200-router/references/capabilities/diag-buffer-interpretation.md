# 能力卡：诊断缓冲区解读框架（时间轴+状态切换+安全事件限流）

## R（原文引用）
> "CPU 提供了一个诊断缓冲区，其中包含的每个条目对应一个诊断事件。每个条目都包含了事件发生的日期和时间、事件类别及事件描述。条目按时间顺序显示，最新发生的事件位于最上面。日志填满后，新事件将替换日志中最早的事件。如果 CPU 断电，诊断缓冲区将保留 50 个最近的诊断事件。"
> ——《S7-1200 系统手册》V4.7，6.1.6 诊断缓冲区，p80

## I（自述）
诊断缓冲区是几乎所有 S7-1200 排障的入口。解读框架四要素：①**时间轴**——条目按时间排序、最新在最上，先建"事件前后顺序"再谈因果；②**状态切换锚点**——CPU 每次上电/STOP/RUN 切换都记录（p80），用它把杂条目分段归组；③**容量语义**——循环覆盖最旧条目、断电只保 50 条，所以"没看到"≠"没发生"；④**限流**——部分安全事件（错误密码登录、访问被拒等，清单见 p81）可在设备组态按时间间隔（1–255 秒/分/小时）汇总，读到的条目可能是"多条合并"。

## A1（合成演练，含可复算数值）
原书未提供解读算例。合成演练：用户报"昨天 14:00 左右 CPU 停过"。读缓冲：14:02 "时间错误，超出最大循环时间" → 14:02 "切换到 STOP" → 14:05 "切换到 RUN"。判读：先有超时后有 STOP（阶梯卡判据），14:00 前后的杂项（如"在线访问被拒"）若无合并组态则各自成条；若该条目重复多行相同时间戳 → 检查是否开启了安全事件限流，统计口径按间隔归并。

## A2（未来触发）
- 场景：任何排障的第一步"帮我看看诊断缓冲区"；复盘停机时间线；缓冲区条目太多无从下手。
- 语言信号：中"诊断缓冲区／看看日志里报了什么／时间轴对一下"；英"diagnostic buffer / read the log entries / timeline"。
- 相邻区分：缓冲区读到"最大周期超时→STOP"后的**机理与处置** → scan-cycle-stop-ladder（两卡共触发：本卡出时间轴，阶梯卡出判据）；具体模块诊断语义（模拟量 32767 等）→ 各专项卡；安全事件清单细目 → p81 表（本卡 B 段引用）。

## E（执行步骤）
1. 输入契约：问题描述的时间窗（"昨天下午"这类模糊窗须先收窄）。
2. 导出/在线读取缓冲区（在线和诊断 > 诊断 > 诊断缓冲区，p80）。
3. 建时间轴：标记所有模式切换（上电/STOP/RUN）为分隔线，把事件归组到各段。
4. 逐段判读：每段内找"第一条异常"（最新在上，倒序找最早的触发源）。
5. 核对限流：重复型安全事件是否被合并（间隔组态 1–255）。
6. 输出契约：事件时间线表（时间 | 事件 | 段号 | 判读）+ 下一张卡/下一步建议。
7. 完成标准：时间窗内每个异常条目都有判读或明确的"无法判读"标记。

## B（边界）
- 反场景：想看"很久以前"的条目——容量循环+断电仅保 50 条，超出窗口手册给不出（诚实缺口，需外部追溯手段如数据日志）。
- 手册口径：条目在"诊断 > 诊断缓冲区"页面（p80）；安全事件限流的完整类型清单在 p81（11 类，含正确/错误密码转在线、检测被操控数据等）。
- 矛盾/勘误：无。
- 外链缺口：各模块专有诊断条目的完整语义 → 模块章节/在线信息系统（如 AINFO 卡覆盖 SM 1231 部分）。
