# 能力卡：HSC 输入点冲突『紊乱情况』（可致人员死亡警告）

## R（原文引用）
> "警告：多个功能分配至单个数字输入通道的风险。将相同 HSC 的多个输入功能分配给一个公共输入点会导致意想不到的结果。多个功能分配给一个触发器产生触发时，无法掌握 PLC 执行功能的顺序。这种情况称为紊乱情况，并且会出现意外情况。要避免絮乱情况，请不要将同一个 HSC 的两个以上的输入功能分配给同一个输入引脚。……这种絮乱情况会引发意外的机械或过程操作，这可能会导致人员死亡、重伤和/或设备损坏。"
> ——《S7-1200 系统手册》V4.7，11.1.3.7，p456

## I（自述）
把**同一个 HSC 的多个输入功能**（如同步输入+门输入）分配到同一个物理输入点时，触发顺序不可预测——手册称为"紊乱情况"，安全警告级别（可致人员死亡）。合规条件：①同一 HSC 不得将两个以上输入功能压到同一引脚；②若确需两个功能共用一个引脚，必须把触发器设置为不同时触发，并注意"下降沿与低电平同时发生、上升沿与高电平同时发生"的等价陷阱。区分边界：**不同 HSC 分享同一输入点**（如 I0.3 同时作 HSC1 与 HSC2 的同步输入）是合法组态，只会生成编辑器警告（p455）。

## A1（合成演练，含可复算数值）
原书未提供数值算例。合成演练：HSC1 组态 CV=Reference1 硬件中断 + 同步输入都指 I0.4。脉冲到来时"先中断还是先同步"顺序未定义 → 计数快照与中断负载可能错位（紊乱）。整改：同步输入挪到 I0.5，或两功能触发条件错开（如同步=上升沿、CV 事件=下降沿，且确认不与"上升沿≡高电平"等价冲突）。

## A2（未来触发）
- 场景：高速计数组态评审；"计数偶尔乱/中断多触发"排查；一个编码器信号要喂多个功能。
- 语言信号：中"同一个输入接两个 HSC 功能／紊乱情况／计数乱跳"；英"chaotic condition / multiple HSC functions one input"。
- 相邻区分：运行时改 HSC 参数（En/New 配对）→ ctrl-hsc-ext-en-new-pairing；CTRL_HSC vs EXT 版本选择 → ctrl-hsc-ext-version-criterion；输入滤波 20 ms（p455 警告，改滤波后短脉冲丢失）属滤波域，本卡只管功能分配冲突。

## E（执行步骤）
1. 输入契约：HSC 组态表（每个输入点承载的功能清单）。
2. 按引脚聚合：同一引脚 → 统计"同一 HSC 的功能数"。
3. 判定：同一 HSC ≥2 个功能同引脚且触发条件可同时满足 → 紊乱风险，整改（挪点或错开触发）。
4. 区分：不同 HSC 共用引脚 → 合法，仅编辑器警告（p455），可放行并记录。
5. 完成标准：每引脚的"功能数 ≤2 且触发互斥"或"跨 HSC 合法共享"结论落档。

## B（边界）
- 反场景：跨 HSC 共享输入（合法）；HSC 输出点被多对象共用（那是 11.1.3.8 的编辑错误问题，p456）。
- 手册口径（p456 说明）：HSC 占用的输入/输出点**无法通过监控表强制**（HSC 完全控制这些点）——调试发现强制无效不是故障。
- 矛盾/勘误（Z3）：HSC"紊乱"正文与警告框在 p455–456 可读（11.1.3.7–11.1.3.9），早期"缺页"记述应下调为"部分可读"——引用一律回 p455–456 原文。
- 外链缺口：无（本条警告手册自足）。
