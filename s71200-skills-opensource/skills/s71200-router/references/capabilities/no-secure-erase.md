# 能力卡：S7-1200 不支持安全擦除（处置要求与设备能力矛盾）

## R（原文引用）
> "停用过程的相关风险：S7-1200 CPU 不支持安全擦除存储卡和内部闪存。因此，在停用过程中，必须妥善处置 CPU 和存储卡，以防丢失专有或机密信息。"
> ——《S7-1200 系统手册》V4.7，p957（15.11 格式化存储卡节内说明；p107 同口径复现）
> （配套注意：Windows 格式化程序会令卡不可用——"请勿使用 Windows 格式化程序或任何其它格式化程序来重新格式化存储卡"，p107）

## I（自述）
设备报废/转售/送修（停用过程）时出现**能力-要求矛盾**：数据合规要求"数据不可恢复地清除"，而 S7-1200 **不支持安全擦除**存储卡与内部闪存——格式化/复位出厂只能让数据"逻辑不可见"，不承诺物理擦除。结论：含敏感程序的设备退役时，物理处置（保留/销毁存储介质、限制流通）是唯一合规路径。附带纪律：SIMATIC 卡不能用 Windows 格式化（会废卡）；必须保留 `__LOG__` 与 `crdinfo.bin`。

## A1（合成演练，含可复算数值）
原书未提供数值算例。合成演练：产线退役 10 台 CPU+卡。按 p957 处置链：复位为出厂（可选格式化卡）→ 仍不视为"数据已安全擦除" → 走物理处置：卡与 CPU 分级登记，含专有程序的介质按公司保密规定销毁或封存。判据：手册口径下任何软件手段都不满足"防丢失专有信息"的最终保证，必须落到物理环节。

## A2（未来触发）
- 场景：设备报废/转售/送修前问"数据擦干净了吗"；审计问安全擦除能力；处置流程编写。
- 语言信号：中"安全擦除／数据清干净／设备退役处置"；英"secure erase not supported / decommissioning / data disposal"。
- 相邻区分：复位出厂的选项与后果 → factory-reset-10-consequences；丢密码清程序 → password-loss-blank-card-erase；换件密码处置 → cpu-swap 卡。

## E（执行步骤）
1. 输入契约：处置对象清单（CPU/卡）与数据敏感级别。
2. 声明设备能力边界：无安全擦除（p957 原文）——软件清除 ≠ 合规擦除。
3. 软件清理（可选，仅为减暴露面）：复位出厂+格式化卡（STEP 7 在线和诊断路径，p956）。
4. 物理处置决策：按敏感级别保留/销毁介质；记录台账。
5. 完成标准：处置台账含"不支持安全擦除"声明与物理处置动作；卡未用 Windows 格式化。

## B（边界）
- 反场景：卡在役重用（清旧作业文件即可，p102/104，非报废）；卡意外被 Windows 格式化（已废，只能重新走 STEP 7 格式化流程恢复可用性，p956）。
- 手册口径：格式化卡对内部装载存储器无影响（p957 说明）；插卡时未重启则内部装载存储器内容保持。
- 矛盾/勘误：无；B10（订货物号 6ES 278-4BD32 缺位，p1102）与本条无涉。
- 外链缺口：数据销毁合规标准（如公司保密规定/行业规范）不在手册范围。
