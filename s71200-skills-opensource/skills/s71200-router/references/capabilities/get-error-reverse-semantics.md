# 能力卡：GET_ERROR 反向语义（ENO=TRUE=有错；接管诊断缓冲区；只留首个错误）

## R（原文引用）
> "如果 EN = TRUE 且 GET_ERROR 或 GET_ERROR_ID 执行，则：ENO = TRUE 表示发生代码块执行错误并提供错误数据；ENO = FALSE 表示未发生代码块执行错误。"（p251）
> "默认情况下，CPU 通过将错误记录到诊断缓冲区来响应块执行错误。但是，如果在代码块中放置一个或多个 GET_ERROR 或 GET_ERROR_ID 指令，即将该块设置为在块内处理错误。在这种情况下，CPU 不在诊断缓冲区中记录错误。"（p250）
> ——《S7-1200 系统手册》V4.7，9.8.8 GET_ERROR 和 GET_ERROR_ID

## I（自述）
GET_ERROR/GET_ERROR_ID 有三个反直觉语义：①**ENO 反转**——ENO=TRUE 表示"发生了错误"（并把错误数据交付），ENO=FALSE 反而是正常；②**接管缓冲区**——块内一旦放了这两条指令，该块的执行错误**不再写诊断缓冲区**，全部转入错误结构（排障时"日志干净"≠"没出错"）；③**只留第一个错误**——首次执行返回块启动以来的第一个错误，之后每次执行返回"上次执行以来"的第一个错误，无历史，执行即清。派生规则：后续错误往往是首个错误的连锁，先修第一个。

## A1（合成演练，含可复算数值）
原书未提供数值算例（错误码表见 p250 表 9-153）。合成演练：FC1 无错误保护，执行中出现 2528（DB 不存在，W#16#9528）。加保护后：GET_ERROR_ID 首次执行返回 16#2528，ENO=TRUE；修复后再执行返回 0 且 ENO=FALSE。若同一次执行里还发生了 2520（损坏字符串），因只留首错，返回值仍是 2528。数值按表 9-153（23 条表项，B 类勘误见 B 段）复算。

## A2（未来触发）
- 场景：块内做错误处理编码；"块明明执行出错但诊断缓冲区没条目"的排障；读懂既有程序里的 GET_ERROR 逻辑。
- 语言信号：中"GET_ERROR 怎么用／ENO 是真怎么还报错／错误没进缓冲区"；英"GET_ERROR ENO semantics / local error handling / first error only"。
- 相邻区分：I/O 直接访问错误（CPU 级，仍进缓冲区且可用 GET_ERROR_ID 访问原因，p75 表 6-19）→ router；块外错误（无保护块崩溃）→ 常规诊断路径；错误码查表（2520–2943）→ p250 表。

## E（执行步骤）
1. 输入契约：目标块类型（FC/FB/OB）与错误处理策略。
2. 在块内添加 GET_ERROR（要细节）或 GET_ERROR_ID（只要 ID）；输出接 ErrorStruct/Word。
3. 用 ENO 作错误分支条件（TRUE=有错），**不要**按常规 ENO 习惯写反。
4. 评审：确认该块错误"进结构不进缓冲区"是团队预期（监控/告警路径要补）。
5. 判停：块内多处 GET_ERROR 只保留能覆盖所有路径的必要点位，避免"第二次执行清掉首个错误"的误判。
6. 完成标准：错误注入测试——人为制造一次访问错误，验证 ENO=TRUE 且错误 ID 与 p250 表一致。

## B（边界）
- 反场景：想让错误进诊断缓冲区（那就别放 GET_ERROR）；处理通信指令 STATUS（OUC/Modbus 有独立错误模型）。
- 矛盾/勘误（R2/R3 教训）：错误码行数=23 条（非 27），其中 2538/9528≡2550/9552、253D/9533≡253F/9535 语义重复（B13）；0000/0001 属正常态非错误——引用"错误码表"一律以 p250 表 9-153 为准。
- 外链缺口：无（指令语义手册自足）。
