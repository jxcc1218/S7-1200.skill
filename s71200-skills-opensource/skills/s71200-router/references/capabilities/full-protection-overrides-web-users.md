# 能力卡：保护等级『完全保护（无访问权）』覆盖 Web 用户权限

## R（原文引用）
> "请注意，如果将 CPU 的保护等级 (页 138)设置为'完全保护（无访问权）'(Complete protection (no access))，则无论 Web 服务器用户权限采取何种设置，'Anonymous' 用户都不具备 Web 服务器的访问权限。"
> ——《S7-1200 系统手册》V4.7，13.7 标准 Web 页面，p694

## I（自述）
Web 登录被拒排障的一条覆盖规则：CPU 保护等级设为"无访问权（完全保护）"时，**无论 Web 服务器用户/权限怎么配，Anonymous 用户一律进不了 Web 服务器**——Web 用户管理（UMAC）不越过 CPU 保护等级。排障顺序因此固定：先查 CPU 保护等级与访问控制（p138–140：完全访问/读/HMI/无访问四档，默认"无访问权"），再查 Web 用户与权限，最后查连接机制。反向结论：想让 Anonymous 访问 Web，必须先在访问等级层面放行（如设读访问等级），且这本身与"请勿启用 Anonymous"的安全建议（p139/p486）冲突——取舍见 B 段。

## A1（合成演练，含可复算数值）
原书未提供数值算例。合成演练：Web 用户配置了"读取文件"权限，登录 Web 仍被拒。检查链：①CPU 保护等级=完全保护 → 根因在此，Web 权限配置再对也没用；②改保护等级为"读访问"并给 Anonymous 分配相应权限 → 登录成功且只见只读页。每步可按 p140 访问等级表（完全访问/读访问/HMI 访问/无访问）复验。

## A2（未来触发）
- 场景："Web 登录不上/Anonymous 进不去"；配置 Web 用户权限后发现不生效；安全基线评审。
- 语言信号：中"完全保护 Web 登录不了／Anonymous 没权限／保护等级覆盖"；英"complete protection blocks web access / anonymous web login denied"。
- 相邻区分：端口不通（80/443 未监听）→ port-protocol-default-state；PUT/GET 需要 Anonymous 的 A1 矛盾 → 本卡 B 段；OPC UA 用户权限 → OPC UA 域卡。

## E（执行步骤）
1. 输入契约：Web 登录账号 + 现象（401/无权限页/连不上）。
2. 查 CPU 保护等级（设备组态 > 保护和安全 > 访问控制）：是否"无访问权（完全保护）"。
3. 若是 → 这是设计行为：要么提升访问等级，要么用具名用户+权限，Anonymous 不可用。
4. 若否 → 查 Web 服务器激活、HTTPS 设置、用户权限映射（p682 权限表）。
5. 完成标准：登录成功并落到预期权限；或明确结论"完全保护下 Anonymous 无法访问 Web"。

## B（边界）
- 反场景：PUT/GET 远程访问启用步骤（p141）要求先启用 Anonymous——与"请勿启用 Anonymous"安全建议（p139）构成 A1 互斥，取舍判据：仅在与该 CPU 通信双方均可控的封闭网络且确需 PUT/GET 时临时启用，公网/开放网络一律不开（另用 BSEND/BRCV 或组态型连接）。
- 手册口径：密码区分大小写；输入正确密码即获该等级全部功能（p139）。
- 矛盾/勘误：A1（p136/p139 vs p141）如上；"仅允许 HTTPS"默认态 A18 争议（p732 称默认、p753 并列 http/https）→ 初始安全状态不可想当然，以实机 Web 服务器属性为准。
- 外链缺口：Web API 完整定义 → S7-1500 Web 服务器文档（D6）。
