# 能力卡：数据日志写满→换新文件续接框架

## R（原文引用）
> "如果循环数据日志文件中存在空记录，则 DataLogWrite 指令将写入下一条可用的空记录。如果所有记录均不为空，则 DataLogWrite 指令将覆盖最早的记录。"（p400）
> "如果要防止覆盖任何数据记录，则可在当前数据日志已存储最大记录数后，使用 DataLogNewFile 指令基于当前数据日志创建新数据日志。新数据记录将存储到新数据日志文件中。旧数据日志文件及记录数据仍保存在闪存中。"（p397）
> ——《S7-1200 系统手册》V4.7，10.9.2 数据日志

## I（自述）
数据日志是**循环文件**：写满后默认覆盖最旧记录（STATUS=0001 提示"日志已满"，p400）。要保数据不丢就走续接框架：写满信号（0001 或程序计数）→ DataLogNewFile 基于当前日志复制记录结构建新文件 → 新记录进新文件，旧文件连同数据留在闪存。前置约束：创建/换文件是多扫描周期操作，**必须等 DONE=TRUE**才能继续写（p397/p400）；旧文件累积会吃装载存储器（与容量预算卡联动），需定期归档清理。

## A1（合成演练，含可复算数值）
原书未提供数值算例。合成演练：RECORDS=1000，程序每秒写 1 条。t=0 创建；t≈1000 s 时 STATUS=0001（写满）；若未处理，第 1001 条覆盖第 1 条。启用续接：在 0001 首次出现时调 DataLogNewFile（等待 DONE）→ 新文件记满再换。每月新增文件数 ≈ 2.6（30 天×86400÷1000），可反推清理周期。

## A2（未来触发）
- 场景："日志开始从头覆盖了怎么办"；要求"数据一条都不能丢"；设计长期记录归档。
- 语言信号：中"日志写满覆盖／DataLogNewFile／换新文件"；英"datalog full overwrite / DataLogNewFile / rollover to new file"。
- 相邻区分：创建前容量怎么算 → datalog-capacity-budget；每次写入至少 2KB 的放大问题 → datalog-2kb-write-amplification；Web 端下载/删除日志（1000 个上限）→ router Web 域。

## E（执行步骤）
1. 输入契约：RECORDS、写入频率、允许的最旧数据保存期。
2. 监测：轮询 STATUS（0001=已满）或 DataLogWrite 完成计数。
3. 满时序：DataLogNewFile → 监视 DONE → DONE 后恢复写新文件（未完成就写=写不进去，p397）。
4. 旧文件处置：Web 服务器 Data Logs 页下载→删除（程序打开中的文件不能删，p713–714）。
5. 完成标准：验证一个满周期：0001 出现→新文件建立→记录续写成功、旧文件可读。
6. 自查：若"换文件后没数据"，第一查 DONE 门控缺失。

## B（边界）
- 反场景：允许覆盖的循环日志（无需续接）；容量算不下（先回容量卡）。
- 矛盾/勘误（A9 同源）：掉电安全口径见容量卡 B 段；"下载并清除"功能在 V4.x Web 已拆成下载+删除两个操作（p1168）。
- 外链缺口：Web 数据日志页的权限要求（读/写文件权限）→ Web 用户权限域卡。
