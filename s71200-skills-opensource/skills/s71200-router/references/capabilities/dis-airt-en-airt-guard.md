# 能力卡：DIS_AIRT/EN_AIRT 跨 OB 共享值三段式保护

## R（原文引用）
> "如果用户程序共享存储器中在程序循环 OB 和中断 OB 之间生成的多个值，用户程序还必须确保在修改或读取这些值时保持一致性。可以在程序循环 OB 中使用 DIS_AIRT（禁用报警中断）和 EN_AIRT（启用报警中断）指令……在代码块中插入 DIS_AIRT 指令，以确保在读/写操作期间无法执行中断 OB。插入读/写能够被中断 OB 更改的值的指令。在顺序结尾插入 EN_AIRT 指令，以取消 DIS_AIRT。"
> ——《S7-1200 系统手册》V4.7，8.4 了解数据一致性，p162

## I（自述）
程序循环 OB 与中断 OB 共享"多个值"（跨指令序列）时，CPU 的单值一致性保护不够用——中断可能在两次指令之间插入执行。三段式保护：①共享值访问序列前插 DIS_AIRT（禁报警中断）；②中间放对共享值的读/写；③序列结尾必须插 EN_AIRT 解禁。同一共享值被通信（HMI/另一 CPU）改写时同样适用：用 DIS_AIRT 延迟中断直到 EN_AIRT。代价：中断 OB 的执行被推迟，中断等待时间变长。

## A1（合成演练，含可复算数值）
原书未提供独立算例。合成演练（以 DWord+Int 两个共享值为例，单值不需本保护，两值打包才需要）：程序段 1 `DIS_AIRT()`；程序段 2 `DB1.total := DB1.total + delta; DB1.count := DB1.count + 1`；程序段 3 `EN_AIRT()`。判据：中断 OB 无论在段 1–3 之间的哪个点触发，都要等 EN_AIRT 后才执行 → 中断 OB 读到的 (total, count) 永远是同一次更新后的配对，不会出现 count+1 而 total 未加的半更新。

## A2（未来触发）
- 场景：跨 OB 读到"半更新"的打包数据（比如一个值新一个值旧）；用户在问中断和主程序抢一个结构体怎么办。
- 语言信号：中"中断把数据改了一半／DIS_AIRT 怎么用／主程序和中断共享变量"；英"DIS_AIRT EN_AIRT / interrupt reads half-updated data / shared value consistency"。
- 相邻区分：**HMI 写入偶发丢失**（优化/标准访问失配）→ optimized-standard-access-pairing（晋级卡）：那是通信可见性缺陷，本卡是 OB 间时序竞争，两卡互写近邻负例；单个 Bool/Word 原子性 → CPU 自动保证（p162），不需要本卡。

## E（执行步骤）
1. 输入契约：共享变量清单（必须在程序循环 OB 与中断 OB 间共享且 ≥2 个关联值）。
2. 定位：主 OB 中访问共享值的代码段首尾。
3. 段首插 DIS_AIRT、段尾插 EN_AIRT，两指令必须成对且在同一执行路径（含提前返回分支）。
4. 复查：EN_AIRT 是否在所有分支可达（漏插等于永久禁中断）。
5. 完成标准：每处共享值序列都有配对的 DIS/EN 对；评审通过。
6. 自查：DIS_AIRT 持续时间越短越好——若程序段很长，缩小包裹范围而不是全程禁中断。

## B（边界）
- 反场景：单个基本类型值（CPU 保持一致性）；纯主 OB 内部变量（无中断竞争）。
- 手册说明（p162）：延迟中断会"影响用户程序的中断等待时间（从事件发生到执行中断 OB 的时间）"——对实时性敏感的中断慎用、包小。
- 矛盾/勘误：无；C-168 为跨文件重复指针（验证组已并 canonical，同口径）。
- 外链缺口：通信请求与缓冲区一致性（PtP/PROFINET 指令缓冲区清单）在 p162 下方"以下指令组"列表，引用时以手册原表为准。
