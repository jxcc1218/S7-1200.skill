# 能力卡：首次 IP 分配流程与『在设备上直接设 IP』双刃剑

## R（原文引用）
> "S7-1200 CPU 不具有预组态的 IP 地址。必须手动为 CPU 分配 IP 地址：要在线为设备分配 IP 地址，请参见'设备组态：在线为 CPU 分配 IP 地址'……"（p491）
> "警告：使用'在设备中直接设置 IP 地址'下载硬件配置。启用……选项的情况下下载硬件配置后，CPU 操作模式无法在 RUN 与 STOP 之间切换，直到设置 IP 地址。在这些情况下，用户设备将继续运行，并可能导致意外的设备和过程操作。"（p490）
> ——《S7-1200 系统手册》V4.7，12.6.3 分配 IP 地址

## I（自述）
新 CPU 上线第一步：S7-1200 出厂**无预组 IP**。项目法：设备组态里设 IP+子网 → 下载时自动写入（p491）。在线法（首次调试常用，p487 四步）：项目树"在线访问"→"更新可访问的设备"（只显示 MAC=无 IP）→ 双击"在线和诊断"→ 功能 > 分配 IP 地址 → 输入并分配 → 再扫描确认。**双刃剑**：设备组态若选"在设备上直接设置 IP 地址"，下载后 CPU 在 RUN/STOP 间无法切换、直到 IP 被设置——而设备可能继续运行造成意外动作（p490 警告）。另一约束：IP 改出子网范围会断 PROFINET 通信（p490）。

## A1（合成演练，含可复算数值）
原书未提供数值算例。合成演练：新 CPU 1214C，PC 网卡 192.168.0.200/255.255.255.0（p486 示例口径）。在线法四步：更新可访问设备 → 仅见 MAC → 在线和诊断 > 分配 IP 地址 → 设 192.168.0.1 → 重新扫描显示新 IP。判据：PC 与 CPU 网络 ID 相同（192.168.0.x）才能直连成功。

## A2（未来触发）
- 场景：新设备上线/换新 CPU；"STEP 7 只显示 MAC 不显示 IP"；调试环境首次组网。
- 语言信号：中"新 CPU 没有 IP／首次分配 IP／只扫到 MAC 地址"；英"assign IP address / no preconfigured IP / MAC only in accessible devices"。
- 相邻区分：**知道 IP 但连不上/被锁** → emergency-ip-recovery（晋级卡；负例必写：找不回 IP→晋级卡，首次设置→本卡）；端口/服务不通 → port-protocol-default-state；T_CONFIG 经程序改 IP → router 通信组态域。

## E（执行步骤）
1. 输入契约：规划的 IP/子网掩码（必须与编程设备同网络 ID）。
2. 选路径：项目下载法（组态写入）或在线分配法（p487 四步）。
3. 若设备组态用"在设备上直接设置 IP"→ 下载前先确认安全（设备继续运行风险，p490），下载后立即设置 IP。
4. 验证：更新可访问设备显示新 IP；PING 通；与 CPU 建立在线。
5. 完成标准：CPU 可被 STEP 7 以新 IP 访问；IP 未出子网范围。

## B（边界）
- 反场景：IP 丢失/不知道 IP 的找回（→emergency-ip 晋级卡）；把 IP 改到子网外导致 PROFINET 断（p490，回退到子网内）。
- 手册口径：必须为子网上所有设备分配唯一 IP（p485）；下载项目时会组态所有 IP（p491）。
- 矛盾/勘误（A23 取舍）：禁用自动协商后果两说——p490 上文说"半双工"，同页选项说明写"端口在 100 Mbps 的半双工状态下运行。如果启用自动协商……全双工"，而 12.6.2 节另处写"自动为全双工操作组态"。取舍：**以 p490–491 操作段为准：禁用自动协商 → 100 Mbps 全双工**（该处为可执行动作定义），"半双工"表述视为排版/措辞不一致，引用时注明。
- 外链缺口：无。
