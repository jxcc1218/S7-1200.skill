# 能力卡：AWP 注释空格疏漏→编译器静默不生成正确代码

## R（原文引用）
> "为 Name 或 Use 子句提供的文本必须用单引号括起来。如果括起来的名称是 PLC 变量或数据块名称，则应使用单引号将整个子句括起来。在 Name 或 Use 子句中，数据块名称和 PLC 变量名称必须用双引号括起来。如果变量名称或数据块名称包含单引号字符或反斜杠，应使用反斜杠将该字符转义。反斜杠在 AWP 命令编译器中是转义字符。"
> ——《S7-1200 系统手册》V4.7，13.8.2.12 Name 和 Use 子句，p732

## I（自述）
用户自定义 Web 页面的 AWP 注释（`<!-- AWP_In_Variable Name='...' -->`）是给"AWP 命令编译器"看的，语法错了**不报编译错误，只是静默不生成正确代码**——变量读/写不生效或页面变量缺失。最常见疏漏是空格与引号层级：Name/Use 子句外层单引号、内部 DB 名与变量名双引号、单引号与反斜杠要用反斜杠转义；`Name='"DB1".Tag'` 的引号-空格结构错一个字符就失效。特殊字符（冒号/尖括号/&/反斜杠）按 p731 规则处理（别名 + 转义）。

## A1（合成演练，含可复算数值）
原书未提供数值算例（p732 表 13-2 为官方示例集）。合成演练：变量名 `ABC'DEF`。错：`Name='ABC'DEF'`（未转义）→ 编译器静默失败，页面无该变量。对：`Name='"ABC\'DEF"'`（反斜杠转义单引号，p732 表）。DB 变量：`Name='"Data_block_1".ABC\'DEF'`。验收法：编译后用浏览器读 `:=变量:` 输出，缺失即 AWP 语法疏漏。

## A2（未来触发）
- 场景：自定义 Web 页面变量不显示/写不进；排查 AWP 注释；HTML 表单提交无效。
- 语言信号：中"AWP 注释不生效／Name 子句／Web 变量读不到"；英"AWP comment syntax / Name clause / silent AWP failure"。
- 相邻区分：枚举映射（AWP_Enum_Def/Use 的 Enum 属性，p729）与片段（Start_Fragment/Import_Fragment）同属 AWP 域但各自语法独立；Web 服务器开关/权限 → full-protection 卡与 Web 域卡。

## E（执行步骤）
1. 输入契约：变量/DB 名称清单（含特殊字符）。
2. 逐条核对：外层单引号 → 内部双引号包 DB/变量名 → 特殊字符反斜杠转义（单引号/反斜杠/冒号/尖括号/&）。
3. 空格检查：`<!--` 与命令、子句间空格结构完整（AWP 注释必须是规范 HTML 注释）。
4. 编译并在浏览器验证 `:=Varname:` 输出与表单写入。
5. 静默失败自查：变量缺失/无效 → 逐字符比对 p731–732 示例表，重点查引号转义与多余/缺失空格。
6. 完成标准：所有声明的变量可读（且可写项可写），页面 UTF-8（p732 说明）。

## B（边界）
- 反场景：Web 服务器未激活/权限不足（那是访问问题，先查 full-protection 卡）；枚举值映射错误（A17 相关，见下）。
- 矛盾/勘误（A17/A7 取舍）：AWP_Start_Fragment 签名 p721 汇总写 [Type][ID]，p729 正文写 [Type][ID][Mode]——引用以 p729 正文（参数定义完整、含可见/隐藏语义）为准，p721 视为汇总缺列；AWP_Enum_Ref 已"不再需要"（p729），但 p732 Name 子句说明仍将其列入——按"兼容存在但不再需要"理解，新代码用 Enum 属性直接关联。
- 外链缺口：无（语法手册自足）。
