# 能力卡：CTRL_HSC_EXT 取代 CTRL_HSC 的版本判据（V4.2 分界）

## R（原文引用）
> "说明：CTRL_HSC_EXT 指令代替了针对 V4.2 或更新版本 CPU 项目的早期 CTRL_HSC 指令。所有 CTRL_HSC 指令功能及多个附加功能可用于 CTRL_HSC_EXT 指令。早期 CTRL_HSC 指令仅能够与早期 S7-1200 项目兼容且不应在新项目中使用。"
> ——《S7-1200 系统手册》V4.7，11.1 计数（高速计数器），p434

## I（自述）
版本分界：CPU 固件/项目 **V4.2 及以上 → 用 CTRL_HSC_EXT**；EXT 是 CTRL_HSC 的超集（全部旧功能+附加功能）。旧 CTRL_HSC 只为兼容早期项目保留，新项目禁用。判据的意义在于：迁移旧项目或混合版本工程时，选错指令轻则功能受限（旧指令无 HSC_Frequency 等新能力），重则与 EXT 代码并存造成维护混乱。决策顺序：先定版本 → 再选指令 → SDT（HSC_Count/HSC_Period/HSC_Frequency）仅 EXT 可用。

## A1（合成演练，含可复算数值）
原书未提供数值算例。合成演练：V4.4 CPU 新项目 → 选 EXT（判据：V4.4 ≥ V4.2）。V3.0 旧项目迁移到 V4.x CPU：设备更换后项目版本升级，计数代码应改用 EXT（旧 CTRL_HSC 仅兼容场景保留）。检查点：指令树里若同时看到 CTRL_HSC 与 CTRL_HSC_EXT，新代码一律用 EXT。

## A2（未来触发）
- 场景：新建 HSC 程序选指令；老项目升级后问"旧指令还能不能用"；迁移评审。
- 语言信号：中"CTRL_HSC 和 EXT 有什么区别／V4.2 用哪个／旧指令还能用吗"；英"CTRL_HSC vs CTRL_HSC_EXT / firmware V4.2"。
- 相邻区分：EXT 用法（En/New 配对）→ ctrl-hsc-ext-en-new-pairing；组态冲突（紊乱）→ hsc-chaos-input-conflict；本卡只回答"选哪条指令"。

## E（执行步骤）
1. 输入契约：CPU 固件版本 + 项目来源（新建/迁移）。
2. 判定：固件 ≥V4.2 且非纯旧项目兼容 → EXT；否则旧 CTRL_HSC（并标注迁移计划）。
3. 新项目硬规则：即使硬件支持旧指令，也用 EXT。
4. 完成标准：项目内 HSC 控制指令版本一致，无新旧混用。

## B（边界）
- 反场景：确实要维护无法升级的旧 V3.0 项目（保留 CTRL_HSC，标明兼容窗口）。
- 手册口径："不应在新项目中使用"是明确禁令，不是建议。
- 矛盾/勘误：无。
- 外链缺口：运动控制轴的计数另属工艺对象域（V3.0→V4.x 运动控制版本迁移差异见 p1168 表，迁移卡引用）。
