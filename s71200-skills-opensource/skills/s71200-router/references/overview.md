## 1. 结构 (Structural)

### 类型

**厂商实操手册**（设备级技术参考 + 工程操作指南）。与"方法论著作"的关键差异：它**不主张、不论证**，而是**规定与定义**——内容以"什么条件下该怎么做"的操作规范、"这个参数意味着什么"的定义、以及"XXX 的规格是 YYY"的数据为主体。

### 一句话主旨

**给出 S7-1200 PLC 从选型、安装、组态、编程到通信与诊断的完整官方操作口径**——把每一个动作、参数与限制写到"照着做就能跑通、出错能查"的颗粒度。

### 骨架（主要部分及其关系）

1. **硬件与安装层**（第 2、5 章 + 附录 A/C/D）：产品形态、功率预算、机械安装、接线接地、备件与迁移
2. **运行模型层**（第 6 章 PLC 概念）：用户程序执行、OB 与优先级、存储区、数据类型、存储卡
3. **工程组态层**（第 7 章 设备配置）：硬件组态、组态控制、防护与安全（UMAC）、时间同步
4. **编程模型层**（第 8 章 编程概念）：块体系（OB/FC/FB/DB）、访问方式、数据一致性、下载与在线同步
5. **指令层**（第 9、10、11 章）：基本指令 / 扩展指令 / 工艺指令（HSC、运动控制、PID）
6. **通信层**（第 12、14 章 + 第 13 章 Web 服务器）：协议选型、连接资源、PROFINET/PROFIBUS/AS-i/S7 通信/OPC UA/Modbus TCP
7. **诊断与运维层**（第 15 章 + 附录 D）：在线诊断工具、故障排查路径、设备更换

**论点之间的关系**: **并列**（不是递进或反驳）。七个部分各自独立、按工程阶段排列；跨部分的耦合点只有少数几处（如"数据类型"约束"通信可传什么"、"连接资源"约束"HMI/OPC UA 混用上限"）。

### 作者要解决的核心问题

**如何让一个具备自动化基础知识的人，在不查阅其它 Siemens 文档的前提下（事实上并不总能做到，见批判），把 S7-1200 从零件装成一台能运行、能通信、能诊断的控制器。**

## 2. 解释 (Interpretive)

### 关键术语（手册中的实际用法，非字典义）

| 术语 | 手册中的用法 | 与常识用法的差异 |
|---|---|---|
| 开放式设备 | S7-1200 硬件本身必须装进外壳/控制柜才能用，柜体保护等级按污染程度选 | 不是"开放标准"的意思，而是"裸机不可直接现场部署" |
| 过程映像分区（PIP0–PIP4） | 决定 I/O 在哪个时机更新；分给 PIP 却不分配 OB，该映像**永不更新** | 常识以为"分区只是优化"，手册里它是正确性前提 |
| `I_:P` / `Q_:P` | 直接访问外围设备输入/输出，绕过过程映像 | 常识以为等价于 `I`/`Q`；手册中两者取值时机不同，且 `I` **无法强制**、只能强制 `:P` |
| 传送卡 / 程序卡 | 同一张 SIMATIC 存储卡的两种互斥用途：批量复制程序 vs 作外部装载存储器 | 用错用途会直接丢程序 |
| 专有技术保护 | 无密码时"局部变量已隐藏"——不是加密，是隐藏 | 易误解为强加密 |
| 优化块访问 / 标准访问 | 两种块访问方式，**必须配对**；不配对会导致 HMI 对 IN/OUT 的写入在 FB 执行期间丢失 | 常识以为"优化总是更好"；手册中它与"标准 DB 才兼容 S7-300/400""PEEK/POKE 必须用标准 DB"直接冲突 |
| 传值 / 传引用 | 接口类型选择决定是拷贝还是引用；手册建议 ARRAY/STRUCT/STRING 用 IN_OUT 以避免额外存储 | — |
| 数据一致性 | 跨 OB 共享值的读写保护问题，需用户自行用 `DIS_AIRT`/`EN_AIRT` 包裹 | 常识以为"读一个变量是原子的" |
| M_BIT（沿存储位） | 每条沿指令必须独占；复用会导致误触发；只允许 M、全局 DB、静态存储器 | 常识以为可以随手指一个位 |
| 装载存储器 / 工作存储器 | 程序、数据日志、配方、Web 页面**共享**同一块装载存储器；工作存储器只装活动配方 | 算错数据日志容量会直接导致下载失败 |
| 活动配方数据块 | 工作存储器里"当前生效的一条配方"，与装载存储器里的配方块成对 | 双 DB 架构是手册唯一有架构味的思路 |
| `Error_Decode`（DPV1 STATUS） | 四字节数组解码：判责任方 / 错误码 / 制造商 | 不区分责任方就无法判断是自己组态错还是设备厂商问题 |
| `GEOADDR` / 硬件标识符 | 用 `GEO2LOG`/`LOG2GEO`/`IO2MOD` 把硬件常量换算掉，硬件重排后程序不必改 | 常识是硬编码地址 |
| TSAP / 连接 ID / 动态资源 | 传输层端口与连接预算：34 个动态资源 + 各类预留/最大值；**加 CM/CP 不增加连接总数** | 常识以为加了通信模块连接数就变多 |
| 看门狗时间 / 重新组态时间（MRP） | 环网重配置硬约束 200 ms，看门狗必须 >200 ms；S7-1200 只有两个端口，无需组态环网端口 | — |
| 27648（模拟量标定） | `SCALE_X`/`NORM_X` 的满量程值；**电压型输入 `NORM_X` 的 MIN 为 -27648 而非 0** | 关键分叉写在示例后的"请注意"里，极易漏读 |
| 特殊模式（S7 通信） | S7-300/400 移植时须手改 `LEN=65535`，且 PROFIBUS GET/PUT 可能强制单向 | — |
| 共享设备 / 智能设备 | 一个物理 IO 设备被两个控制器分配子模块 / 一个 CPU 作 IO 设备交出传送区 | — |
| 紊乱情况（HSC 输入点冲突） | 输入点分配错误可导致"紊乱"，手册就此发出**可致人员死亡**的警告 | 命名温和，后果极重 |
| AWP（Automation Web Programming） | 指令集形式嵌入 HTML：`<!-- AWP_In_Variable Name='"DB".Var' -->` 等；**注释内空格疏漏会导致编译器静默不生成正确代码且不报错**（p721） | 常识以为编译器会报错；手册自认静默失败 |
| 片段 DB / 控制 DB / requesttab | 用户自定义 Web 页面的三段式结构：片段（HTML 片段）、控制（决定发送哪些片段）、入口页组态 | 手册称其为"高级"用法 |
| `Data_Area_Array` | 用 8 个区域描述把 Modbus 地址映射到 DB，替代直接过程映像访问 | — |
| `HR_Start_Offset` | 保持寄存器基址重定位量，用于兼容不同 Modbus 主站的 40001 起始习惯 | 同一知识在 p829/858/886/922 反复出现且细节不同，须先合并口径 |
| MB_MODE | 0 = 标准寻址；1xx = 扩展寻址，决定地址→功能代码的映射 | 反直觉：不是"模式编号"而是"寻址风格" |
| 强制的持久性 | 强制值存在 **CPU** 而非监视表格里：关掉 STEP 7 仍生效；且**无法强制 HSC/PWM/PTO 占用的 I/O 点** | 常识以为关掉表格即解除 |
| 轮询架构（PtP/Modbus） | 串行通信全靠用户程序循环调用发送/接收；PtP 的"OB 循环时间内须执行 Receive 两次"是量化不丢帧判据 | 常识以为通信是后台自动的 |

### 核心命题（用自己的话）

1. **容量先于功能**：功率预算、连接资源、装载存储器、嵌套深度、保持性容量——先算清上限，再谈能不能实现；手册中每一条"超限"都指向确定性故障。
2. **配对约束普遍存在**：优化访问要配对、PROFINET 设备名两处要一致、组态控制的数据记录要与实际模块匹配、DB 写保护与指令参数要呼应——不配对即失效。
3. **硬件组态不是下载就生效**：安全向导、访问控制、时间同步、HSC 输入点等均要求"组态 + 下载 +（必要时）循环上电"三步到位。
4. **诊断从"责任方判定"开始**：错误码结构（DPV1 STATUS、`Error_Decode`、`8x222` 参数序号反查）都以"先判谁错"为第一层。
5. **区别"组态期的门"与"运行期的墙"**：访问等级、密码、保护等级都在工程组态层生效；手册自己承认"密码保护不适用于用户程序指令的执行""PLC 到 PLC 通信不受访问等级限制"。
6. **可恢复性有边界**：丢密码只能空卡擦除、V3.0→V4.x 下载后不可撤销、CPU 不支持安全擦除——手册明确划出了"回不去"的操作。
7. **能力缺口以外链补**：运动控制、PID、OPC UA 细节、AS-i、TINFO/AINFO 结构等大量内容以"参见另一份文档"代替（≥9 处），离线环境下手册不自足。

### 论证链

**这本手册没有论证链**——它是规范文档，命题以上级标准、产品定义与厂商设计决定为依据，而非以论据推导。它给出的"理由"通常是后果警告（"否则会导致……"）而非证明。

> 因此，下游 skill 的 **B（Boundary）** 不应写成"作者论证的局限"，而应写成**适用条件与不可外推边界**：版本绑定、生态依赖、工具链前提、以及手册自认的能力缺口。

## 3. 批判 (Critical) ★

> 全部条目均有原文依据（页码来自实际读取）。厂商手册的"批判"不是驳倒作者，而是**标出可执行性的真实边界**。

### 3.1 版本与生态绑定（最硬的局限）

- **版本强绑定 V4.7**：UMAC 仅 V4.7 存在；TLS 1.3 需组态 V4.x；SNMP 默认值在 V4.6 被翻转；MC 指令 ENO 语义在 V4.0 翻转；数据日志在 V4.1 起取消 `//END` 标志；同一张 ID 取法表里并存 V3.0/V4.0 两套规则（p299）；OPC UA 用户降级不移植。
- **工具链强绑定**：几乎所有操作流程以 STEP 7 / TIA Portal 的 GUI 路径为唯一入口（右键属性、选项对话框），并反复把细节外推给"TIA Portal 信息系统"与支持站点（本手册内 ≥10 处，全区间 ≥9 处外链替代正文）。**脱离西门子工具链，这些流程不可执行。**
- **许可与生态前提**：OPC UA 需运行系统许可证（订货号 6ES7823-0BA00-2BA0）；固件只能从西门子官方渠道下载；文档更新优先于本手册。

### 3.5 未被证明的假设

- **假设读者手上有全套西门子文档与工具链**（多处外链离线不可达）。
- **假设"循环上电"是无害的通用手段**（多处用它替代解释）——但诊断章节明确"不要循环上电"，两处口径相反。
- **假设时钟正确性**：证书示例（p526）已于 2024-08 过期，而手册是 2024-12 版——手册自身示例即已失效。
- **假设硬件就是它声明的样子**：性能、精度、寿命（闪存写入换保持性容量，p419）的风险均转移给用户的自律。
- **假设"默认即安全"**：Web 服务器默认 HTTP 也可访问（p753），"仅 HTTPS"需读者主动收紧，而手册只说这是"西门子建议"（p681/685/686/694 四次逐字重复同一段建议）。
- **假设 IP 已通**：全部在线诊断能力都附带"必须在设备中分配 IP 地址"的硬前提（p951/953/954/955/957/958/959 反复出现），即诊断链建立在未论证的前提之上。

### 3.6 能力缺口与不兼容（外链与生态封闭）

- **整章外链**：CP 1243 系列的"连接、要求、应用、块说明、附件和组态示例"全部指向三本 CP 操作说明（p944）——第 14 章标题含"通信处理器"却**不给组态**；3964(R) 协议行为用 S7-300 CP 341 手册解释（p759）；USS 结构要求与扩展错误码指向驱动器手册（p906/807/810/913）；Web API 只覆盖 S7-1500 Web API 子集（p752）；轨迹功能细节指向外部在线手册（p977）。**结果：多条方法论链在本手册内是断的。**
- **他牌不兼容**：Siemens 中继器**只支持 PROFIBUS**，Modbus RTU 超 32 设备必须外购第三方中继器（p874）；USS 用 PROFIBUS 连接器接线（p812）；Modbus 客户端端口从 2000 起、服务器 502 但"第三方可能不同"（p822/826/838/855）；CSV 为 USA/UK 格式，非英语环境须手工走文本导入向导（p713/754）。
- **能力缺口自陈**：Web API 不支持 LWord/LInt/LTime_Of_Day/S5Time/LDT（p752）；`DATA_PTR` 不接受 Bool 及其数组（p786/787）；**S7-1200 不支持安全擦除存储卡与内部闪存**（p957）——与 IT 侧数据销毁要求不兼容；保护等级一旦丢失**手册未给恢复步骤**（p982）。
- **连接耗尽的唯一恢复路径是等待 30 分钟**（p753）；数据日志与用户文件各有 1000 条硬上限，超限须把 CPU 置 STOP 才能显示和删除（p713/715）。

### 3.7 最强反对意见

> **"这本手册把'厂商设计决定的后果'包装成'工程必然'。"**
>
> 它系统性地省略了两类东西：① **为什么**（上限、边界、默认值的依据）；② **替代方案**（没有一处第三方品牌或跨厂商方案对照，全区间仅 p300 一处声明符合 IEC 61131-3，其余为西门子专有）。因此它训练出的读者会形成一种"西门子工具链 = 唯一正确路径"的默认假设——而这恰好也是它的商业模式。
