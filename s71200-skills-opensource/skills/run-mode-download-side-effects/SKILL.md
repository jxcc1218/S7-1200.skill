# run-mode-download-side-effects — RUN 模式下载：准入闸门、副效应与临时失败指令

## R — Reading（原文）

> "在 RUN 模式下，一次最多可下载 20 个块。如果要下载的块多于 20 个，必须将 CPU 置于 STOP 模式。"（p968；p970 同文重复）

> "如果 CPU 处于 RUN 模式且程序发生更改，则 TIA Portal 首先尝试在 RUN 模式下下载更改。"（p968，说明）

> "如果删除一个输出的控制逻辑，则在下一次上电循环或切换到 STOP 模式之前，CPU 将始终保持该输出的最终状态。"（p974）

> "如果删除了正在运行的高速计数器或脉冲输出函数，则该高速计数器或脉冲输出将继续运行，直至下一次上电循环或切换到 STOP 模式。"（p974）

> "如果在同一个 OB 执行中重试该指令，它将失败。"（p975，12 条临时失败指令表后说明）

## I — Interpretation（自述）

RUN 下改程序是成熟的在线变更手段，但它有**三张必须先看的清单**。第一张是**准入闸门**：一次 ≤20 块（超了必须 STOP）；块类型准入表——FC/FB/变量表可建/覆盖/删，DB 与背景 DB 可建/删/覆盖，OB 只能覆盖不能建删，Web 服务器 DB 绝不可在 RUN 下下载；默认（未启用"下载而不重新初始化"）时 **DB 结构变更不可下**（p974 概括口径）。第二张是**副效应清单**（全部静默、不报错）：删了某输出的控制逻辑 → 该输出**冻结在最终状态**直到下次上电或 STOP；删了运行中的 HSC/PWM → 它们**继续跑**；以首次扫描位为条件的逻辑本次**不会执行**（FirstScan 只随 STOP→RUN 置位，不随 RUN 下载置位）；DB 当前值不能被覆盖。第三张是**临时失败指令表**：DataLogCreate/Open/Write/Close/NewFile/Clear/Delete（STATUS=80C0）、READ_DBL/WRIT_DBL（82C0）、Create_DB/Delete_DB（80C0）、RTM（80C0）——下载激活期间调用会临时失败，RLO 失败；正确处置是**在随后的 OB 执行中重试**，同一 OB 执行内重试**必然再失败**。另有不可逆点：启用"下载而不重新初始化"后加变量受 100 字节默认预留区约束，而禁用它重新下载 = 全量重新初始化、现值丢失。

## A1 — Application Example（标注演练：阶段 1.5 已核实数 + 纸面复算）

**书中数字素材（表 B-1 算例在功率预算卡已用）与本卡的验收数**：20 块上限（p968/p970 两处同文）；预留区默认 **100 字节**（p972）；12 条临时失败指令与 2 个错误码（80C0/82C0，p975 逐行）。

**【合成演练，按原书规则复算】** 需在 RUN 下：①删除 Q0.5 的控制逻辑（原逻辑每周期写 0）；②新增"首次扫描初始化"段；③给优化 DB 新增 3 个 DInt（12 字节）。
1. 准入核算：改动涉及块数 ≤ 20 ✓；③为新增变量、优化块、12 ≤ 100 字节预留 ✓（启用"下载而不重新初始化"时）；②属逻辑新增（FB 覆盖）✓ → 全部可 RUN 下发。
2. 副效应预判：①Q0.5 **冻结在删除瞬间的最终状态**——若恰为 1 则持续输出 1 且不报错（需补偿动作：手动清或触发 STOP→RUN）；②首次扫描位**不置位**，新初始化段本次不执行，等一次 STOP→RUN；③新变量取起始值、现有值保留。
3. 时序风险：下载激活窗口内若 OB1 调 DataLogWrite → STATUS=80C0、ERROR=TRUE、RLO 失败；正确处置 = **下个 OB 周期重试**；在同一 OB 内立即重试 → 必再失败（p975 原文判据）。
4. 反例（判停出口）：若再要把某 Struct 加成员 → 结构变更，默认口径下 **RUN 不可下**，转 STOP 全量下载。
复算依据：四条副效应、准入清单、错误码均取 p968–975 原文；演练未造手册外规则。

## A2 — Future Trigger ★

**触发场景**：
1. "不停机改程序 / make changes without stopping the CPU / download in RUN"——在线变更的入口问句。
2. "在线下载有什么风险？下载前要检查什么？"——变更管理评审。
3. "RUN 下下载报错了/某指令在线上偶发 80C0"——下载数据日志/DB 读写指令临时失败。
4. "删掉这段逻辑后输出怎么不动了？"——下载后副效应排查。
5. "在线加几个变量会不会丢数据/要不要重新初始化？"——预留区与重初始化取舍。

**语言信号**：RUN 模式下载 / download in RUN mode、在线下载/在线变更 / online change、20 个块 / 20 blocks、不重新初始化 / without reinitialization、首次扫描位 / first scan、临时错误 80C0/82C0、输出冻结 / output frozen。

**与相邻 skill 的区分**（初稿）：**STOP 下的全量下载/上传/备份** → router（15.4–15.16 常规在线工具域）；**下载后 CPU 转 STOP 或报严重错误** → scan-cycle/诊断 router 卡排查触发"CPU 转 STOP"的原因；本卡管的是"下载成功前后"的准入与行为预测。与"下载而不重新初始化扩容 DB"细则（结构冻结清单、保持性预留区）同源——router 侧保留细则卡，本卡持决策视图。

## E — Execution（可执行步骤）

**输入契约**（缺则先问）：①改动清单——涉及哪些块、每块改动类型（新建/覆盖/删除/结构变更/加变量）；②CPU 当前模式与是否满足四项"要求"（支持 RUN 更改、编译无错、可通信、CPU 无错误，p974）；③若含加变量：块是否优化、预留区字节数（默认 100）、新增字节数、新增保持性字节数；④程序里是否调用 12 条临时失败指令中的任一条；⑤现场安全评估——RUN 下载"立即影响过程操作"（死亡级警告，p968），是否获授权。

**步骤**：
1. **Step 1 准入双闸**（判停点）：闸 A = 块数 ≤ 20；闸 B = 逐块查准入表（OB 只覆盖、Web 服务器 DB 禁下、默认口径下 DB 结构变更不可下——判据链：优化块？启用"下载而不重新初始化"？改动是否限新增变量/改起始值/注释？三条全 ✓ 才走 RUN 扩容，否则 STOP）。任一闸不过 → 转 STOP 下载，本卡结束。✅ 完成标准：块数与每块类型结论落表。
2. **Step 2 副效应预判表**：对照四条逐项问——删控制逻辑的输出有哪些（记录当前值）？运行中 HSC/PWM 是否被动过？有无首次扫描位条件逻辑？是否试图覆盖 DB 当前值（→ 不可，改方案）？✅ 完成标准：每条副效应给出"存在/不存在 + 补偿动作"。
3. **Step 3 预留区核算**（如含加变量）：新增字节数 ≤ 预留区（默认 100）且新增保持性字节 ≤ 保持性预留区；超了 → 下载时 TIA 会报错，须先增大预留区（启用状态下**不可**改预留区/删条目——只能禁用→重初始化下载→重启用，代价 = 现值丢失，不可逆点）。✅ 完成标准：字节数对比表。
4. **Step 4 执行与临时失败处置**：点下载前确认 TIA 会"先试 RUN"（不想走 RUN 就先手动切 STOP）；下载激活窗口内若 12 条指令之一报 80C0/82C0 → 定性为临时错误，**下个 OB 周期重试**，禁止同 OB 内重试，禁止据此停机检修。✅ 完成标准：下载完成 + 若有临时失败已按重试契约处理。
5. **Step 5 下载后核验**：执行副效应补偿（清冻结输出/安排 STOP→RUN 使 FirstScan 逻辑生效）；在 TIA 完成前不安排其它在线任务（下载期间 TIA 被独占）。

**输出契约**：RUN 下载检查单（字段：块清单｜块数/20｜每块准入结论｜副效应×4 与补偿｜预留区 对比｜临时失败指令暴露面与重试计划｜下载结果）。**约定**：重试次数上限手册未定——建议"跨 OB 周期重试直到成功或下载确认完成"为现场约定；预留区大小缺定量方法（N5 缺口），不造公式。

## B — Boundary（边界与失败模式）

- **反场景**：STOP 下全量下载/固件更新/存储卡操作 → router；下载失败因网络中断（15.18.6 加载预览对话框）→ router；CPU 因下载异常转 STOP 的深度排查 → scan-cycle/诊断 router 卡；只是改 HMI 画面/参数值 → 不涉及块下载。
- **手册警告的失败模式**：①死亡级警告——RUN 下载"立即影响过程操作"，须授权人员执行（p968）；②TIA Portal **默认先试 RUN**——大改动（>20 块）时部分更改已生效后才提示转 STOP，设备进入"改了一半 + 即将强制停机"状态（规避：点下载**前**手动置 STOP）；③四条副效应全部**静默**（输出冻结、HSC 照跑、FirstScan 不置位、DB 现值不可覆盖），无报错可查；④"下载而不重新初始化"启用时无法删条目/改预留区——禁用它重下 = **现值全部重新初始化**（唯一明示的不可逆丢数据点）。
- **A3 矛盾处置（取判据不取站队）**：p968"可添加到数据块结构并在 RUN 模式下下载" vs p974"不会覆盖 DB 的结构更改"——取舍判据：**仅**优化块 + 启用"下载而不重新初始化" + 增量限"新增变量"时按 p968（可下，新变量取起始值）；其余一切结构变更（加 Struct 成员/改名/改数组大小/改类型/改保持性）按 p974 需重新初始化。
- **阶段 0 批判盲点**：预留区"该设多大"手册无定量方法（N5 诚实缺口）；12 条临时失败指令仅覆盖激活窗口期，下载前后的其它报错不在该表——错误码需回各指令表查。
- **相邻易混淆**：与"下载而不重新初始化"router 细则卡共享触发词；分流 = 决策/副效应/准入（本卡）vs 预留区操作步骤细则（router）。
